# 初版实现：架构、接口与演示规则

版本：v0.1（2026-11-01）\
对应分支：`feature/first-playable`\
性质：可运行初版的实现记录。所有数值均为**可替换的演示参数**，不是最终策划规则。

## 3. 月度结算顺序

`Simulation.tick()` 固定顺序（每步验证条件，失败整体回滚到本期开始前快照）：

1. 重置企业/城市月度统计，时间 +1 月。
2. 记录各商品期初总库存（用于守恒审计）。
3. 人口自然变动（确定性 RNG 噪声）。
4. 城市间迁移：先算双方结果，再原子提交；不产生/删除人口。
5. 企业计划：利用率、产能岗位需求、现金/信贷约束。
6. 劳动力匹配：先裁员（每月最多 8%），再公共部门优先招聘，企业按固定顺序补员；企业只能从本城失业人口招聘。
7. 创建市场台账（期初可售供应 = 企业库存 − 自用投入保留）。
8. 长期贸易合同优先执行（先验证库存/需求/资金与可用信贷，再在提交点同时融资和转移货物）。
9. 企业生产资料采购：先本城市场，再区域市场补货（跨城市企业间交易，价格含运输加成）；只有存在投入缺口时才申请营运资金信贷。
10. 生产：按配方消耗库存、产出，记录产出价值/中间投入/增加值。
11. 居民消费：按人口群体、人均需要、价格弹性求期望数量，用上一月可支配收入约束预算；先本城，再区域市场补货。
12. 区域外净出口（演示）：只吸收超出目标库存的消费品。
13. 价格调整与市场统计。
14. 企业财务：工资（可用信贷）、所得税/企业税、利息、债务偿还、股息、产能调整。股息按玩家持股与总股本拆分：玩家所得进入玩家现金/累计分红，余额才计入居民收入；`player + other === 企业实际支付`（两位小数舍入）。
15. 城市财政：个人所得税、企业所得税、公共工资、福利；计算本月居民收入供下月消费。
16. GDP：按生产记录汇总增加值；更新历史。
17. 库存守恒审计与全部不变量检查；失败则恢复快照并返回错误。
18. 写日志、保存 RNG 状态、修剪历史。

## 4. 关键不变量

- `城市总人口 = 就业 + 失业 + 非劳动力`
- `就业 = 公共部门员工 + 各企业员工之和`
- `企业岗位分布合计 = 企业员工数`
- `世界人口 = 各城市人口之和`
- 企业库存、现金、玩家现金非负；债务非负
- 市场成交 ≤ 有效需求；本地成交 ≤ 可售供应；未满足需求非负
- 市场期末库存 = 该城企业该商品库存合计
- 库存守恒审计：`期初 + 产出 − 中间投入 − 居民消费 − 区域外出口 + 跨城净转移 = 期末`
- GDP = 各生产记录 `产出价值 − 中间投入价值` 之和；不把工资、营业额或股票市值直接相加。

`tests/simulation.test.ts` 覆盖初始/24/36 月不变量、固定种子重现、跨城货流、注资、非法注资不改状态、存档往返/损坏/版本过新、GDP 口径。验收修复新增：
- `tests/dividends.test.ts`：玩家分红拆分、无持股、四舍五入守恒。
- `tests/save-validation.test.ts`：缺 `publicSector`、字段类型错误、损坏 JSON、版本过新、读取失败不改状态、损坏自动存档不被覆盖。
- `tests/trade-atomic.test.ts`：资金不足但可借到少量资金时不成交且零变化、成功交易全量提交、无效主体零变化。

## 5. 商品与生产

商品 8 种：

- 消费品：食品、成衣、日用品
- 生产资料：谷物、纤维、布料、金属件、能源

配方（示例）：

- 食品 ← 0.62 谷物 + 0.04 能源
- 成衣 ← 0.85 布料 + 0.03 能源
- 日用品 ← 0.22 金属件 + 0.08 能源
- 布料 ← 0.95 纤维 + 0.03 能源
- 金属件 ← 0.25 能源
- 谷物/纤维 ← 0.02 能源
- 能源 ← 无材料投入（仅劳动/产能/资金约束，明确的演示简化）

生产率（单位/员工/月）与初始产能集中在 `src/data/demo-data.ts`；企业产能 = 员工 × 生产率 × 科技系数 × 1.08。

## 6. 市场、贸易与信贷（演示机制）

- **城市市场**：每城每商品独立价格与台账；可售供应排除企业自用投入保留，避免同一批原料月内反复转卖。
- **长期合同**：`TRADE_ROUTE_SEEDS` 中的 8 条路线优先执行，覆盖谷物、纤维、金属件、布料；买方可用营运资金信贷，但融资只在库存/需求/资金/信贷全部验证通过后的提交点发生；失败不留下现金/债务/库存/统计变化。
- **区域市场补货**：本城不足时企业/居民可从其他城市企业购买，价格 = 买方城市市场价 × 卖方价格系数 ×（1 + 距离运输加成，最高 12%）；成交写入跨城贸易流。撮合按卖家逐笔原子成交，允许跨多个卖家的部分成交并记录未满足需求。
- **区域外净出口**：只对消费品；每月最多吸收产出的 30%，并保留至少 0.2 个月库存；价格为本城市场价的 90%；付款来自区域外。这是开放经济演示，不对应真实国家。
- **营运资金信贷**：企业现金不足时可借入最多 6 个月基础工资额，月息 0.5%；用于采购/工资，避免单月回款时点造成流动性死亡螺旋。
- **债务重组**：债务超过信用额度 80% 且现金低于工资 20% 时，减免 50% 债务并注入 0.35 个月工资的营运资金（明确标注为演示稳定机制）。
- **运输成本/物流容量**：未实现；运输加成只是价格楔子，不模拟运输企业、运力或损耗。

## 7. 存档格式

```json
{
  "formatVersion": 1,
  "gameVersion": "0.1.0",
  "savedAt": "2026-11-01T00:00:00.000Z",
  "world": {
    "seed": 20261101,
    "rngState": 123456789,
    "time": { "year": 2026, "month": 2, "tick": 1 },
    "cities": [],
    "companies": [],
    "tradeRoutes": [],
    "player": {},
    "history": [],
    "log": [],
    "lastTick": {}
  }
}
```

- 槽位：`autosave`、`manual-1`、`manual-2`、`manual-3`；每次成功推进自动写 `autosave`（损坏自动存档被检出后，本会话暂停自动写入以保留原文件）。
- Electron 主进程校验槽位名、≤8MB、JSON 结构，临时文件 + rename 写入。
- 读取时 `parseSave` 校验格式版本、世界结构、全部不变量；失败给出原因，**不覆盖当前进度**。结构校验覆盖城市 `population/publicSector/market/lastMonth/technology/politics/realEstate`、企业岗位/库存/财务、玩家持股、贸易路线、历史/日志和 `lastTick`；缺字段/类型错误返回明确路径，而不是抛 `TypeError`。
- 自动存档损坏时：启动进入新世界并提示，`autosaveDisabled=true`，不删除/不覆盖原文件，UI 显示“自动存档已暂停”；显式读取有效手动存档或确认新世界后才允许再次自动写入。
- 版本高于 `SAVE_FORMAT_VERSION` 明确拒绝；低版本预留迁移入口（当前只有 v1）。
- 浏览器模式（`npm run dev:web`）回退到 localStorage，仅用于开发/截图；Electron 使用 IPC。

## 8. 确定性

- `DeterministicRng`（mulberry32）状态保存在 `world.rngState`；每期自然增长噪声与迁移抖动使用同一 RNG。
- 所有遍历使用固定顺序（城市/企业/商品/路线排序）；对象键顺序稳定。
- 相同初始状态 + 相同操作 + 相同种子 → 相同 `WorldState`；测试逐字节比较 12 期后的 JSON。
- 时间只在模拟内用 `{year, month, tick}`；`savedAt` 是存档元数据，不参与结算。

## 9. 玩家操作

- 初始现金 2,000,000，身份为独立投资者（演示）。
- 可向任意企业注资 5 万–500 万：玩家现金减少、企业现金增加、按当前账面股价增发股份、玩家持股增加、企业产能按演示汇率提升（每 2000 万信用点最多 +15% 产能）。
- 企业实际分红时，按 `玩家持股 / 总股本` 拆分；玩家所得进入现金，`dividendsReceived` 累计，事件日志与月度快照可查看。非玩家股东部分才进入城市居民收入。
- 注资会改变企业岗位需求/产能，从而影响后续就业和生产；不是纯 UI 数字。
- 未实现：股票二级市场、控制权/董事会、并购、破产清算、政治参与。

## 10. 科技、政治、房地产

三者均有城市关联初始状态并展示，但均为 `initial-only`：

- 科技：等级/研究点/生产率系数；当前只以固定系数进入产能，研发投入、扩散、企业研发未实现。
- 政治：支持率/执政党/选举倒计时；支持率只参与迁移吸引力，选举、政党、政策未实现。
- 房地产：均价/租金指数/空置率；只展示并参与迁移吸引力，住房市场/土地交易未实现。

UI 中必须明确显示“初始展示，系统未实现”，不提供无功能按钮伪装完整系统。

## 11. 演示参数入口

全部集中在 `src/data/config.ts` 的 `DEMO_CONFIG`：时间、参与率、自然增长、迁移、工资/税/福利、消费倾向/弹性、价格调整、信贷、股息、玩家初始资金、UI 节奏。`DEMO_CONFIG.meta.assumptions` 同时用于游戏内“参数与假设”面板。

## 12. 已知限制

- 区域外净出口、运输加成、债务重组是演示稳定机制，不是最终经济设计。
- 结构性失业可能出现（例如铁谷食品业收缩），当前没有再培训、产业政策、失业救济之外的主动劳动力政策。
- 政府财政可赤字；福利按可用资金支付，公共工资仍按名义额支付。
- 不为每个居民建模；没有家庭、技能、教育、年龄结构。
- 城市地图为固定模块化布局；没有土地购买、建筑建造/升级、道路编辑。
- 科技/政治/房地产未进入真实结算。
- 未实现股票二级市场、控制权、破产、国家/军事/外交。
- 资源：Rasak 主城市美术未获取；当前使用 Kenney 备用城市体系，UI 使用 Kenney UI Pack。详见 `docs/assets/ASSET_REPORT.md`。

## 13. 待架构负责人决定

1. 是否接受当前“区域外净出口 + 营运资金信贷 + 债务重组”作为首版稳定机制，还是改为更严格的封闭经济/银行系统。
2. 城市间贸易的价格基准：当前区域补货按**买方城市价格**结算（把稀缺租金转给卖方）；是否改为到岸价/离岸价/关税模型。
3. 公共部门规模与财政规则：是否允许持续赤字，是否引入债券/税收政策。
4. 劳动力市场：是否保留每月最多 8% 裁员的平滑规则，是否加入服务部门吸收结构失业。
5. 科技/政治/房地产的下一步优先级与数据权威边界。
