# 架构与数据边界

Electron 负责桌面容器和安全的存档接口；Phaser 负责地图及交互；界面读取只读视图、提交命令；独立的 TypeScript 模拟层处理规则，不依赖 Phaser、Electron 或 DOM。

人口核心拥有城市人口及经济状态；劳动力拥有岗位匹配；企业拥有岗位需求和薪酬政策；商品目录拥有静态定义；生产拥有配方和企业库存；市场拥有可售库存、价格、订单和成交；经济模块依据可追溯的生产记录计算简化增加值；贸易负责运输状态。金融、政治、科技、房地产各自拥有其领域数据。避免并行维护互相冲突的员工总量。

人口迁移、雇佣、商品交易及运输使用集中协调的原子操作：先验证全部条件，再整体提交；失败不得留下部分变化。每期验证人口 P=E+U+N、雇主分配=就业、岗位之和=雇主人数、库存非负、成交不超过有效供需。生产投入与产出有记录，GDP 避免重复计算中间投入。

使用确定排序、固定种子随机数和统一时间；保存种子与随机状态、时间、状态和格式版本。月度为原型候选，允许以后调整。以版本化存档和明确失败提示应对不兼容数据。原型演示数值和简化公式不得误标为最终策划规则。
