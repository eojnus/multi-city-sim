# 机制扩展实现记录 v0.2：数据边界、结算顺序与暂定规则

版本：v0.2（2026-11-01）\
分支：`feature/mechanisms-foundation`（基线 `08aefb4`）\
性质：可运行原型的实现记录。除明确标注为“用户已确认”的少数规则外，所有参数与规则均为**暂定演示方案**，不是最终策划。

## 1. 本次新增/调整的模块

| 位置 | 职责 | 数据权威 |

## 2. 股份与权利（用户已确认 + 暂定）

用户已确认：

- 股票分两类：有投票权、仅分红。
- **股票市场买入**：企业作为买方在股票市场买入的股票都必须有投票权。
- **企业融资**：融资企业可对**不同出资方**分别约定是否给予投票权；出资方即使是另一家企业，也可以获得仅分红股份。每个出资方的股份、数量与权利必须分别记录。
- 股东、董事、经营控制权不是同一概念，不能默认持股即控制企业。

暂定（集中配置、可替换）：

- 每家企业发行 `voting` 与 `nonVoting` 两类，两类按股同额分红（`config.governance.defaultDividendPayoutRatio`）。
- 每张投票权股票一票；董事会席位按投票权股份比例用最大余数法分配（`boardSeats = 5`）。
- 企业默认由职业经理人经营（`control.operator = 'management'`）。更换经营者须由投票权持有人提出 `operatorAppointment` 议案并表决通过。
- **个人**二级市场买入是否带投票权尚未决定：当前演示对个人买入不限制类别，玩家可主动买入两类；个人融资注资默认取得有投票权股份。该行为由证券模块统一判断，便于以后替换。
- 融资要约接受前不改变任何资金或股份；拒绝不产生义务。
- 企业通过融资取得的仅分红股份可以正常持有、出售并获得股息，但不产生投票权；市场买入限制只按买方身份和订单方向验证，不影响企业出售合法持股。

## 3. 股息与资金流向

- 企业按 `dividendPayoutRatio`（默认 0.6，可由议案改变）从当月利润中派息，受现金与工资储备限制。
- `securities.distributeDividend` 按实际持股逐笔分配；合计严格等于派发额（余数给最后一个持有人）：
  - 玩家 → 玩家现金、`lastDividend`、`dividendsReceived`；
  - 企业 → 该企业现金与 `lastMonth.dividendIncome`（不进入居民收入）；
  - 居民投资实体 → 按配置比例拆成**留存**与**返还**两部分：返还部分（默认 70%）直接从实体现金扣除并进入城市居民可支配收入，留存部分（30%）留在实体现金用于投资。两部分互斥。
- 因此居民实体现金只会因留存股息、储蓄划转和股票交易变化；返还金额不会同时留在实体现金和消费预算中。
- 每城每月从居民可支配收入中划出 6%（`investors.savingsRate`）进入投资实体，**同时从下月消费预算中扣除**；这是收入用途划分，不新增货币。
- 本版不把“企业持有股份所得”或“玩家所得”重复计入居民收入。

## 4. 二级市场

- 订单簿：`world.securities.orders`（买/卖、限价、剩余股数、下单 tick）。下单时校验现金/持股，但**不冻结**资金或股份；撮合时再次校验，不足则缩减数量或跳过，绝不产生部分扣款。
- 撮合：同一股份类别内，买价 ≥ 卖价才成交，成交价取卖方限价；按限价与 id 确定性排序。订单在 `orderTtlTicks` 后失效。
- 同一持有人不会与自己撮合；居民投资实体的自动买卖单每月按最新账面价重挂（卖价约 ×1.02、买价约 ×0.98），避免旧限价长期偏离市场或实体对倒消耗流动性。
- 二级交易资金从买方流向卖方，**企业不因二级交易获得资金**；只有一级融资（融资要约/玩家注资）才使资金进入发行企业并增加发行量。
- 居民投资实体每月按可替换规则下单：小额卖出提供流动性；现金充足时买入投票权股份，接近持股上限时改买仅分红股份。
- 企业买方只能下投票权类别的买单（下单与读取校验双重约束）。

## 5. 居民投资实体与人口

- 每城 3 个实体（`groupsPerCity`），`populationShare` 合计为 1；represented people 由城市人口 × share 派生，**实体不是额外人口**。
- 实体名称与合计持股可出现在股东结构中；**实体内部现金/明细不在玩家界面展示**。
- 迁移与自然增长只改变城市人口；实体的 `populationShare` 保持不变，资产不随个人迁移移动。这是初期简化：人口迁入迁出不会带走或带来投资实体资产，交付文档明确列出。
- 新世界的实体初始资金是演示初始条件（`initialCashIncomeMonths`）；**旧存档迁移时初始资金为 0**，避免凭空创造货币。

## 6. 董事会与表决

- 结算月内顺序：`ensureGovernance` → 自动投票（玩家除外）→ 到期议案计票并应用结果 → 重选董事 → 企业财务 → 基于本月利润提出下期议案。
- 议案目前两类：`dividendPolicy`（把派息比例调到 1.0）与 `operatorAppointment`（更换经营者）。两者都会产生可观察的企业状态变化。
- 计票：赞成票权重 > 反对票权重才通过；平票或无人投票视为否决；玩家缺席视为弃权。
- 自动投票立场是暂定规则：居民投资实体赞成提高股息，企业持有人反对（保留资金），其他弃权。

## 7. 政府牵头的跨城协议

- 协议由城市政府（`createdBy: 'government'`）或明确标注的演示入口（`'demo'`）发起；**不把玩家无条件当成市长**。
- 参与企业逐个接受/拒绝；拒绝方条目标记为 declined，不产生资金或库存变化。
- 每条 item（买方、卖方、商品、月数量、单价、月份）独立校验、独立原子提交；失败只标记该 item，不留下部分扣款/货物转移。
- 履约失败后该 item 停止执行；协议内全部条目结束后协议为 completed 并注明是否部分失败。已结束协议只保留最近 10 条，进行中的不受影响。
- 价格 = 买方城市市价 ×（1 + 与 `markets/intercity` 相同的运输加成）；接受阈值集中在 `config.agreements`。

## 8. 月度结算顺序（v0.2）

1. 归档 `lastMonth → previousMonth`，重置本月统计、实体当月股息、证券当月成交。
2. 人口自然变动 → 迁移（原子）。
3. 企业计划（读取 `previousMonth`）→ 劳动力匹配。
4. 长期贸易合同 → 政府协议履约 → 自动组织新协议（每 3 月最多一条）→ 清理历史协议。
5. 创建市场期初供应（在合同/协议改变库存之后）。
6. 生产资料采购（成交后才按实际支出补足营运资金）。
7. 生产（受员工、产能、原料共同限制）。
8. 居民消费 → 区域外出口 → 价格与市场统计。
9. 治理：补齐治理记录 → 自动投票 → 计票并应用 → 重选董事。
10. 企业财务：工资、税、利息、还债、按持股派息、产能调整；随后提出下期议案。
11. 城市财政与居民收入（含居民投资实体返还的股息）。
12. 居民可投资资金划转（从消费预算扣除）。
13. 融资要约生成与企业/实体自动决策 → 居民与企业下单 → 二级撮合。
14. 玩家通知（按身份与投票权筛选）。
15. GDP、历史、库存守恒与全部不变量；失败整体回滚。
16. 写日志、保存 RNG 状态、裁剪日志。

## 9. 不变量（新增）

- 每家企业两类股份齐备；`sum(classes.issuedShares) = company.totalShares`；每个类别 `sum(holdings) = issuedShares`。
- 企业作为买方的**市场订单**只能是有投票权类别；融资持有的股份可以是任意类别（不得据此报错）。
- 玩家持股镜像与证券权威记录一致。
- 居民投资实体现金非负；同一城市 `sum(populationShare) = 1`；id 唯一。
- 董事会/议案/经营控制引用的企业、持有人有效；票数非负。
- 协议条目 `deliveredQty ≤ qtyPerMonth × months`、`paidValue ≈ deliveredQty × unitPrice`。
- 通知 id 唯一。

  - 企业发行量无效、玩家持股超过发行量等无法安全推导的情况：**明确拒绝并提示原因**，不臆造股份或资金。
- 版本高于 2 明确拒绝；损坏 JSON、缺字段、类型错误、不变量失败均不覆盖当前进度。

## 11. 通知（暂定）

- 通知只写入 `world.notifications`，由 `notificationVisible` 在生成时过滤：
  - 个人：分红等玩家自身事件，始终可见（金额低于阈值由调用方过滤）。
  - 企业 + 表决：仅玩家持有投票权股份时可见；无投票权不会收到要求投票的通知。
  - 企业 + 分红：玩家持有任意股份即可见。
  - 企业 + 重大变化/融资/协议：玩家持股 ≥ 5%（可配置）或玩家为经营者；控制权/董事会等重要事件对有投票权的小股东可见。
  - 城市：仅当 `player.roles.mayorCityId` 为该城；市长选举未实现，演示场景需在界面明确标注。
- 通知 id 确定性生成；最多保留 120 条；已读状态随存档保存。
- 存档失败/自动存档暂停不写入世界通知，而是作为 `GameStore.systemNotices` 显示在通知窗口顶部，使用易懂语言。

## 12. 已知限制与待决事项

- 股份定价只有账面价（现金 + 库存 + 产能 + 常数 − 债务），没有订单簿深度、做市或真实估值；两类股份同价。
- 投资者资金持续累积（缺少债券、存款、房地产等出口）；自动投资规则保守，成交有限。
- 董事会席位每月重算；没有任期、累积投票、代理投票或法定人数。
- 居民实体资产不随人口迁移移动；这是简化，未做个人资产归属。
- 政府协议由规则自动配对，没有谈判、期限外退出、违约罚则或政府预算参与。
- 城市内部视角、世界地图与 Rasak 素材状态未改变。
- 购买与借款关系的暂定行为（成交后融资）仍需用户确认。
