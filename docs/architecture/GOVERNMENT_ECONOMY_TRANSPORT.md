# 企业经营、政府与交通：开发架构

基于 `feature/mechanisms-foundation` 的 `b50d6b5`。用户已确认方向和待定事项以 `docs/design/GAME_DESIGN_DISCUSSIONS.md` 为准。本文约束实现边界，不把演示公式、参数和本文件的实现建议变成用户已确认的规则。

## 数据权威与职责

- 企业实体、所有权和经营数据继续由已有 `companies/`、`securities/`、`corporate-governance/` 分别管理。`companies/ai/` 只负责根据有限可见信息生成计划/命令，不绕过资金、库存、岗位、权利和交易校验。企业经营者与董事会、股东、政府的权限区分，已接受的多企业贸易协议中企业有权拒绝。
- `population/` 负责人口与就业状态；`investors/` 的居民群体代表既有人口，不另生人口。`companies/lifecycle/` 负责企业设立和退出的流程、主体数量限制及结果协调。公司持股依旧由证券系统处理；不能因倒闭删除其他主体的现金或无记录地抹除货物、股权和债务。
- `politics/` 管理候选人、领导人的身份及明确的被动特性与政府决策；`government/` 负责财政、税收及拨款；`policies/` 负责政策定义、生效状态、预算、期限与结果记录。非玩家政府按城市弱项与领导人倾向选择政策；玩家为市长时政策由玩家选择，不被自动代选。
- `transport/` 管理政府主导的城内/城际公路和铁路、建设、运营与逐期容量统计；商品实际买卖和资金流继续走 `markets/`、`trade/` 和 `agreements/`，禁止建立绕开商品和资金权威的第二套交易。当前不做私人交通设施或私营交通运营。
- `core/`/`contracts/` 负责时间、可复现种子、跨模块交易、验证和存档迁移。界面提交命令、展示只读结果，不直接改写权威状态。集中控制阶段顺序和当前/上期数据，失败事务不留部分改变。

## 核心已确认规则

1. 不同企业有不同的经营目标和风格；新企业可成立、旧企业可倒闭。创办结合人口机制，现有企业和城市政府也可成立企业。需要限制投资者、城市企业数量及企业/政府的创办数量；这些限制的确切口径、固定还是动态及数值未决定。
2. 政府可征税并以财政资金推行政策；玩家当市长时由玩家选择政策。非玩家政府依据城市弱项与领导人倾向施政；多个候选人和领导人具备影响发展领域的被动属性。
3. 已确认纳入 15 项政策：新增招聘补贴、稳岗补贴、职业培训、公共岗位计划、初创扶持、企业纾困、设备与扩产补助、重点产业扶持、研发资助、教育投入、跨城贸易支持、交通基础设施投资、失业救助、住房支持、税收调整。均需通过可观察的真实模拟作用，不以空按钮、只变展示数值或未接入规则代替。政策金额、目标、期限、叠加等未定，应集中配置并标注暂定。
4. 用户确认城内交通与城际交通，首批公路和铁路，由政府主导，不做交通私有化。城际交通容量随网络建设提高；容量不限制成交数量或交易额，超过后按比例减少销售企业该笔跨城贸易收益。**不得再从企业已有现金中额外扣款或另收惩罚费。**
5. 交通容量统计口径、惩罚公式、无连接/零容量处理、买方实际付款与收益减少的精确账务关系、是否叠加普通运费都待定。可采用确定性、集中配置且有充分说明的临时结算规则，但必须满足上一条、账目守恒、明确买卖双方款项以及没有凭空发币/隐形罚款；报告方案供用户后续决定。不得把建议公式当成用户已批准。
6. 世界地图仍是虚构世界的一小片平面区域，城市内部视角未定；不得借交通改造强行改为真实地图或决定等距视角。Rasak 尚未取得和核验。

## 演示可实施性与存档
- 对尚无底层的技能、住房、研发、设备与基础设施，建立与政策闭环匹配的最小运行数据和规则，例如财政支出与目标主体的状态、后续就业/研发/住房或产能结果之间有因果关联；不能只为 UI 更改一次数字或声称完整系统已建成。所有时长、分配阈值、上限等是可调整演示方案。
- 对企业成立/倒闭先建立最小可运行闭环：有实际创办主体、资金来源、数量限制与新增企业；退出处理员工、资金、库存、协议、持股、债务及历史记录，并说明未覆盖的法律与估值规则。所有权变更须与现有存档、证券不变量和未完成的议案兼容。
- 不要把未确定的政策细则、选举规则、交通费用、企业规模上限等写为既定策划；在交付报告列出全部临时假设。游戏界面只显示玩家需要理解的内容，不展示系统调试信息。
- 扩展 `SAVE_FORMAT_VERSION` 的迁移路径，保留真实 v1/v2/v3 存档的城市、人口、企业、库存、资金、股权和投票快照、时间及随机状态；迁移不能静默删除资产或破坏原文件。损坏/不可读存档不得被后续自动存档覆盖。做真实旧存档迁移和新版本往返验证。

## 实现状态（v0.3，2026-11-02，待验收）

- `companies/ai/strategy.ts`：按风格、现金、库存、需求、补贴生成经营计划与可读原因；`companies/planning.ts` 应用计划；不绕过资金/劳动力/库存/产能校验。
- `companies/lifecycle/lifecycle.ts`：三类主体创办、数量与投资者限制、扩产、倒闭清算与记录；`core/initializer.ts` 初始化。
- `politics/politics.ts`：确定性候选人/领导人、任期与选举、玩家参选/演示身份、领导人行业加成与领域倾向；`politics/electionFunds.ts` 处理参选费用转账。
- `policies/`：`definitions.ts`（15 项政策元数据）、`query.ts`（只读效果）、`policies.ts`（启动、AI 选择、月度执行、财政支出）；`government/treasury.ts` 是财政流水与支出上限的唯一入口。
- `transport/network.ts`：政府主导的城内/城际公路铁路、建设、维护与容量；`transport/settlement.ts`：跨城路径的期末统一容量结算与账目记录；`markets/`、`trade/`、`agreements/` 只登记待结算销售，不建立第二套交易。验收修复后采用【暂定】“差额退回买方”：买方净支付 = 卖方实得，差额不再无解释消失；最终账务规则仍待用户决定（见 `ACCEPTANCE_FIXES_v0.4.md`）。
- `labor/workforce.ts`：技能最小状态；`markets/markets.ts` 使用城内配送效率；`production/production.ts` 使用技能、领导人行业加成与重点产业加成。
- `core/save.ts`：`SAVE_FORMAT_VERSION = 4`，v1→v2→v3→v4 迁移链；新增字段的结构校验与不变量在 `core/invariants.ts`。
- 全部数值、上限、期限与公式在 `data/config.ts`，均为【暂定】；用户已确认规则仍以上文与讨论文档为准。交付证据见 `docs/development/DELIVERY_REPORT_v0.4.md`。
