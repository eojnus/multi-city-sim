## 3. 规则与实现明细

### 3.1 §一 验收遗留修复

**1) AI 政策月预算 = 当月合计额度**

- 复现（修前，实测）：岚港 90% 失业、第 2 月两项 AI 危机政策，体检月预算 4,672,713.66，
  两项 `referenceBudget` 各 4,672,713.66 → 合计 9,345,427.32（2.00×），预留/借款 6,226,713.66
  > 额度。来源三处叠加：决策层每项都拿满整月额度；`preparePolicyFunding` 求和各分项；
  未预留路径按“每项 budget/剩余月数”各自给额度。
- 修后：`policies.ts` 以当月体检 `budget` 为 **quota**，对当月全部在行 AI 危机政策按
  `policyReferenceBudget` 权重做最大余数分配（Σ分项 = min(quota, Σ需求)，每项 allocation ≤ 自身需求），
  `claim/reserved/unpaid` 全部按分项封顶；公共岗位实发工资按 `fiscal.publicWages` 真实支付记录
  归属（不受分项额度硬性截断，超出部分单列 `publicWagesOverQuota`，不伪造成实支）。
  永久化字段：`PolicyFundingMonth.quota / policyBudgets / publicWagesAttributed / publicWagesOverQuota`
  （全部 optional，旧档缺省安全）。
- 实测：修后 quota = 4,672,713.66，分项 2,336,356.83 + 2,336,356.83 = 4,672,713.66；
  spent+unpaid = 3,890,356.83 ≤ quota。默认种子 72 月每月 quota = 600 万，典型分项
  失业救助 300 万 + 公共岗位 300 万，实支 499.9 万（见第 7 节）。
- 保持：政府借款/发债仍走既有规则、资金真实到账；85% 借款上限、100% GDP 破产不变；
  玩家市长城市 AI 不代选/代发/代借（玩家保留财政决策权）。

**2) 公共岗位统计（人数 ≠ 人次）**

- 新增 `PolicyState.publicJobsMonths: PublicJobsMonth[]`（每城保留 24 个月，累计字段全期）：
  `jobsAdded`（本月新增岗位）、`headcount`（月末实际在岗人数）、`jobsRemoved`（本月撤销岗位）、
  `wagesPaid`（本月实付并归属公共岗位政策的工资）、`jobsAddedCumulative`、`personMonthsCumulative`
  （Σ各月 headcount，明确标注“人次”）、`jobsRemovedCumulative`、`jobsOutstanding`。
- 报告与面板：`aiPolicyStats` 覆盖 active + 当月结束/撤销政策，真实岗位不再对 publicJobs 恒 0；
  报告新增“公共岗位”行（新增/在岗/撤销/实发 + 累计岗位/累计人次/净在岗）。
- 实测：t12/t72 在岗 476 人、实发工资 199.9 万/月；累计新增 4,760 岗位、累计在岗 30,940 人次、
  累计撤销 4,284（人次 ≠ 新增人数）。

**3) 债券跨城迁移微小权益**

- 方案：不新增存档字段，保持“本金=份数×面额”不变量，把份数从 0.01 粒度改为内部全精度
  `units = principal / faceValue`（面额 1000 时 1 分 = 1e-5 份，优于要求的 1e-6 份级）；
  迁移移出本金 = round2(源本金 × fraction)，只乘一次；目标按分币精确分配到各实体再推份数；
  合并持债后 units 由合并本金/面额重算，不再相加。
- 守恒实测（4 信用点复现例）：源本金 1000→996、目标 0→4，合计 = 发行本金 1000；
  份数 0.996+0.004=1=soldUnits；10 次×4 信用点累计正确；到期本金/利息、付息、破产兑付、
  存读档往返、二次读取幂等全部通过；残余仅“不足 1 分”的浮点尾差（全账本最小记账单位），
  留在源持债本金继续参与后续拆分/兑付。

### 3.2 §二 商品价格

配置（`config.market`，全部可配置）：

| 参数 | 值 | 含义 |
|---|---|---|
| `initialPriceFactor` | 0.95 | 开局价格 = 基础价 × 0.95 |
| `shortageRiseSpeed` | 0.30 | 涨幅 = 缺口率 × 0.30（缺口率 = 未成交有效需求 ÷ 有效需求） |
| `surplusFallSpeed` | 0.12 | 跌幅 = 过剩率 × 0.12（过剩率 = 超出覆盖量×阈值部分 ÷ 覆盖量） |
| `competitionFallSpeed` | 0.08 | 同城卖家>1 且价格高于锚价时按卖家数与溢价压价 |
| `reversionSpeed` | 0.03 | 每月向锚价回归 3%（高价必回归；低价仅在真实需求/成本压力时上调） |
| `maxMonthlyChange` | 0.15 | 单月涨跌上限（同限） |
| `stockSurplusThreshold` | 1.6 | 期末库存超过“成交覆盖量×1.6”视为过剩 |
| `costAnchorFactor` | 1.0 | 锚价 = max(基础价, 上月单位生产成本中位数 × 1.0) |
| `costAnchorMaxFactor` | 1.6 | 成本锚上限（相对基础价），防止异常成本推飞价格 |
| `minPriceFactor` / `maxPriceFactor` | 0.55 / 2.2 | 价格上下限 |

- **进口口径修复（任务书复现例）**：旧实现用 `demand − sold`（`sold` 只含本地成交）算短缺，
  需求 100 / 本地 60 / 进口 40 会被当成“缺口 40”推价。新实现只用 `ledger.unmetDemand`——
  该字段在跨城进口成交后已被冲销（企业采购路径与居民进口路径同口径），因此进口满足的需求
  不算缺口；居民“买不起的 unmetFunding”也不在 demand 内，不推高价格。
- **过剩与竞争**：过剩用“本地成交 + 跨城进口”的覆盖量衡量（避免把进口已售出的货再算积压）；
  同城卖家数 > 1 且价格高于锚价时额外压价。
- **回归与成本锚**：锚价取本城该商品生产者上一完整月 `(COGS + 工资 + 维护费) / 成交单位` 的中位数，
  clamp 到 `[基础价, 基础价×1.6]`；价格高于锚时每月回归，低于锚时仅在存在真实需求/成本压力时上调，
  没有需求不制造上涨。
- **指标区分**（报告逐城逐商品输出）：居民有效需求 `consumerDemand`、企业原料需求
  `producerDemand`/计划 `producerRequired`、本地成交 `sold`、跨城进口 `intercityImported`、
  区域外出口 `externalExport`、可售供给 `supply`、期末库存 `closingStock`、缺货 `unmetDemand`、
  缺钱 `unmetFunding`、基础价、成本锚、当月涨跌幅。
- 消费税仍在含税标价内：价格调整只影响 `market.price`，不改变 `splitConsumptionTax` 拆分，
  不重复征税/重复计算进口、库存或需求（测试覆盖“价格规则不伪造成交量”）。

### 3.3 §三 企业竞争、生产与招聘

- 新增 `src/simulation/companies/pricing.ts`：报价 = 市场价 × `priceFactor`，内部 `priceFactor`
  保留 6 位小数（修复旧实现每步 round2 到 2 位、调价被舍入吞掉），每月至少 1 分钱可见变动；
  夹在 `[0.85, 1.15] × 市场价` 且不低于单位成本 × 1.03；市场按单价升序成交，报价更低的企业
  自然获得更多订单；同时参考同城与可达跨城对手报价（含运输加成），有让价逻辑。
- 需求估计（`production-plan.ts`）：本城可支付缺货份额 + 资金缺口折算（5%×份额）+ 降价机会
  （5%×份额×可降价空间）+ 可达跨城市场（×全国产能份额×运价可达性×0.5）；竞争按企业份额分摊，
  防止每家企业把全城缺口重复算成自己的订单；潜在部分只按吸收比例进计划。
- 增产：有盈利 + 真实可支付缺货 + 上月设备利用率 < 80% → 突破 ±20% 平滑，直接用现有设备增产
  并招工（先现有设备→真实原料→招聘），设备利用率低时不再只靠买新设备扩产。
- 减产/裁员/卖设备：滞销积压与经营困难时合理减产、裁员；闲置设备+经营压力+无缺货才挂单出售；
  v1.4 初始实物出资锁定期内当行业设备整段不出售（修复 v14 守恒回归）。
- 创业 AI（`founding.ts`）：同城同行业近 3 月新办 ≥ 3 且供给/需求 > 1 直接跳过；评分加
  饱和/羊群惩罚；维护费进入单位毛利评估。
- 基本工资规则不变（未降基础工资、未恢复奖金）。

### 3.4 §四 设备月度维护费

- 新增 `src/simulation/equipment/maintenance.ts`。
- **计费公式**：每类设备月维护费 = 企业持有该类设备台数 × 所在城市该类“新设备”当月市场参考单价 × 1%，
  逐类求和；`rate = config.equipment.maintenanceMonthlyRate = 0.01`。
- **持有时点（D1）**：每 tick 开头（`advanceTime` 之后、任何设备买卖/挂单/破产之前）快照
  `company.maintenanceBase`（各类型台数）与 `company.maintenancePrices`（该城当月月初参考价）；
  当月买入（含月中挂单后成交）下月起计费；当月卖出/挂单/返还/破产仍按月初台数计当月费用
  （防止月末交易/挂单逃费）。没有 tick 的直调路径（测试/工具）回退当前台数与当前价。
- **覆盖范围**：初始实物出资设备、新购设备、二手设备、闲置设备、停产期间设备全部计费。
- **费用归属**：独立期间费用，本月应计全额（已付+欠付）进入 `preTaxProfit`
  （所得税/净利/分红/奖金/破产/纾困都看到）；现金支付进 `operatingCashFlow`；不资本化进库存或
  设备购置成本；同一企业同一月幂等只结算一次。
- **资金去向（D2）**：收款方为模拟范围外“城市外部设备维护服务商”；月度独立流水
  `world.equipmentMarket.maintenanceMonth`（含 `byCity`、按类别台数/费用）+ 历史
  `maintenanceHistory`（默认保留 60 月）；不计入设备厂收入、政府税收或任何模拟内主体收入。
- **现金不足**：先按既有规则真实融资（`requestCompanyWorkingCapital`，放款进债务并计息）；仍不足记
  `company.maintenanceArrears`，规则一致：欠费未清不得分红；已有欠费不再为维护费新增借款
  （避免以贷养欠）；清算时先用企业现金补收，确实收不到记服务商坏账（只留痕，不制造模拟内资金）。
- **面板**：企业面板显示台数、计价单价、月维护费、支付状态（含欠付），损益表新增维护费行。
- **存档兼容**：全部字段 optional、缺省 0/回退，不升 `SAVE_FORMAT_VERSION`；旧档读取后下一 tick
  自动补齐快照并开始计费，不重复创建设备、不抹除历史资产。
- **流水口径修复（集成期发现）**：月度流水的“月末欠付余额”原按增量从 0 累加，跨月存量在清算
  注销时会被重复扣减，72 月实测出现 -2,839 的负余额；已改为“月初存量初始化 + 本月增量”，
  并新增 12 月逐月对账测试（流水月末欠付 = 各企业在营欠付合计，非负）。
- 配置：`maintenanceMonthlyRate=0.01`、`maintenanceArrearsBlocksDividends=true`、
  `maintenanceArrearsBlocksFinancing=true`、`maintenanceHistoryMonths=60`、
  `maintenanceWriteOffOnLiquidation=true`。

### 3.5 §五 企业退出与僵尸企业

- 修复根因：`checkBankruptcies` 原 `if (wage <= 0) continue;` 使零员工/零工资企业永远跳过后续判定。
- 新判定（D6，配置 `lifecycle.bankruptcy.idleExitMonths=6`、`idleFixedCostCoverMonths=1`）：
  - `CompanyAiState.idleMonths`：读**上一完整月** `previousMonth` 的 `produced ≈ 0` 且
    `sold + exported ≈ 0` 时 +1，任一经营活动即清零；保护期（`max(minAgeMonths, newCompanyGraceMonths)`）
    内清零；
  - `idleMonths ≥ 6` 后，若“现金 + 可用授信 < 1 个月固定成本（基础工资 + 设备维护费 + 偿债）”且
    无可行恢复计划（本城/可达跨城可支付需求、正毛利、生产资产）与纾困观察期 → 走
    `liquidateCompany` 清算（设备处置/初始设备锁定期返还/库存注销/债务/股东/员工/名额释放全部复用）；
  - 短于门槛的暂时停业不清算；“可恢复的暂时停业”与“长期无经营能力”两类均有测试。
- 实测：默认种子 36 月内出现“连续 6 个月无产出且无销售、现金+授信不足以覆盖 1 个月固定成本”
  的僵尸企业清算记录；72 月仍有 idle 计数高但现金/授信充足的停业企业（未清算，符合“有恢复能力”
  边界，见第 9 节）。

### 3.6 存档容量（集成期发现并修复）

- 现象：v1.6 世界（企业数接近上限 160/城、银行/证券/债券/维护费流水完整）在桌面验收中推进到第 15
  个月后存档失败，提示“存档过大”。实测 15 个月世界 `serializeSave` 文本已有 **12.09MB**，超过旧的
  8MB 上限（`src/platform/saveBridge.ts` 与 `electron/saveIpc.ts` 各一处）。
- 修复：两处上限统一提高到 **64MB**，错误文案同步为“超过 64MB 限制”；其余存档校验/迁移逻辑不变。
- 依据：12.09MB 为真实状态实测（companies 401 家；最大分项 banking 2.84MB、companies 1.56MB、
  householdFinance 0.79MB、securities 0.75MB），提高上限不伪造数据、不裁剪真实账本。

## 4. 价格与维护费计算示例

以下示例均代入上表配置，四舍五入到 2 位。

1. **跨城进口满足需求不推价**：需求 100、本地成交 60、跨城进口 40、`unmetDemand=0` → 缺口率 0，
   短缺项 0；若价格 52.25、锚价 55 → 回归项 = (55/52.25−1)×3% ≈ +0.16%，月末价 52.33。
   同一需求但没有进口（`unmetDemand=40`）→ 缺口率 0.4 × 0.30 = +12%，月末价 58.52。
2. **严重短缺封顶**：需求 100、成交 40、`unmetDemand=60` → 0.6×0.30 = 18% → 受单月上限限制 +15%。
3. **过剩回落**：需求/成交 50、期末库存 500 → 覆盖量 50×1.6=80，过剩率 (500−80)/50 = 8.4 → clamp 2 →
   2×0.12 = 24% → 跌幅封顶 −15%（另有小额回归）。
4. **设备维护费**：某城新工业设备参考价 200,000/台、企业月初持有 10 台工业设备 + 4 台农业设备
   （参考价 120,000）→ 10×200,000×1% + 4×120,000×1% = 20,000 + 4,800 = **24,800/月**；
   其中 20,000 进入企业税前利润（无论是否开工），资金流向模拟范围外服务商。
5. **成本锚**：食品生产者上月单位成本（COGS+工资+维护费）/成交 = 60，食品基础价 55 →
   锚价 = clamp(60, 55, 55×1.6=88) = 60；价格 52 时每月向锚价回归 (+60/52−1)×3% ≈ +0.46%
   （同时若存在真实缺货会更快上涨）。

|---|---|
| 失业率 | 失业 ÷ 劳动力（就业+失业） |

## 9. 已知问题与如实结论

1. **高失业未解决**：72 月失业率 93.4% / 84.7% / 87.4%，仍在 80%–93% 区间；企业端现金大量囤积
   （三城企业现金合计约 89 亿）但居民收入与购买力不足，企业不扩招。价格与竞争规则按需求响应，
   但没有创造就业的机制性闭环。
2. **食品基本需要覆盖仍低**：72 月 24.2% / 22.2% / 30.0%（早期 t6 曾达 56.9%–67.3%），
   跨城进口真实发生且计入覆盖率（进口只计一次），但本地产能与有效需求不匹配。
3. **债务上升**：72 月负债率 78.5%（high）/ 50.6%（watch）/ 60.9%（watch），主因债券到期滚动
   与 AI 政策借款（每月约 500 万）持续累积；未触发 100% 破产（36 月内三城破产 0 次）。
4. **行业集中**：创办 AI 防羊群生效后仍出现 agriculture 类大量创办（岚港 81 家、青原 82 家），
   与食品加工/纺织比例失衡；food 企业数量从 t12 的 25 家降到 t72 的 12 家。
5. **长期停业但现金充足的企业未退出**：72 月有 idle 计数高达 35–42 月的企业仍存续，因为
   “现金+授信 ≥ 1 个月固定成本”未满足清算条件；这是 D6 规则的明确边界（有恢复能力不清算），
   但会产生“占名额的停业企业”。
6. **价格高于基础价**：t72 食品价 79.64/85.27/77.28（基础 55），成本锚在部分城市达到上限
   88（1.6×）；原因是真实单位成本（工资/维护费）高于基础价，规则允许合理偏离，未强制压回。
7. **公共岗位规模有限**：在岗 476 人/城 vs 失业数十万，政策只能覆盖很小一部分。
8. **测试环境噪声**：容器偶发 `[vitest-worker]: Timeout calling "onTaskUpdate"`（进程 exit≠0 但断言
   全绿）；报告按“断言结果”判绿并逐块记录，未隐藏失败。
9. **性能**：企业数接近上限（160/城）后单月 tick 约 2–5 秒，176 月规模的 economy-stability 测试
   单文件约 15–25 分钟，全量回归分块执行。
