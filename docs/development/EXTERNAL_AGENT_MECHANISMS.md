## 目标：可运行的机制扩展

### A. 修复已知基础问题

完成 `MECHANICS_FOUNDATION.md` 中存档保护、上月销售记录、零员工生产约束、政治支持率迁移方向的修复。对采购预借资金的未决规则，保留透明可追溯的暂定行为并说明影响；不得擅自声称用户已决定。保留既有正常存档和模拟运行能力。

### B. 企业、股权与董事会

- 每家企业保留独立现金、库存、商品、股权、股票及董事会；把持股和经营控制分开。支持有投票权和仅分红两类股票，并记录持有人、类别、发行数量、持有数量及权利。
- 支持对不同出资方分别提供不同类别的融资方案；一方接受后出资并获得约定权利，拒绝时无资产变化。至少覆盖玩家、企业和居民投资实体的可扩展类型；防止发行超额或资金/股份复制。
- 实现最小可运行的董事会、议案及有权持有人的表决流程，结果对一项明确的企业决策产生可观察影响。明确演示规则；不暗示已经实现完整公司法或用户已决定席位/控制权规则。
- 根据已约定权利分红，避免把同一股息同时计入居民、企业和玩家；不剥夺既有持有人权利。

### C. 股票市场与居民投资

- 建立最小可运作的股票发行和二级买卖：验证实际买方现金、卖方股数、持股权利和价格后原子结算；区分融资收入归企业、存量股票买卖收入归卖方。不能凭空生成股票、买家资金或默认总能成交。
- 企业作为买家在股票市场购入的股票必须有投票权；该限制不自动推广成个人买入规则。个人市场购买权利未决定，应使用可配置且明确标注的演示方案。
- 每个城市至少有多个由居民组成的投资群体，拥有独立资金与持股，收入、消费、可投资资金、分红与买卖的流向可追溯；群体的资金来源不得凭空生成，避免将原有居民股息统计重复计入。群体不作为额外人口，城市人口变化及迁移须维持资产与人口一致；如果采用初期简化，写出限制与一致性校验。
- 自动投资基于可替换的规则而非逐居民 AI；供给、预算、存量与需求决定是否成交。界面不展示居民投资实体内部明细。

### D. 企业贸易与政府牵头协议

- 继续支持企业直接跨城商品交易；增加由政府牵头、跨两个或以上城市、涉及多家独立企业的协议。
- 每家被邀请企业均可接受或拒绝；拒绝不产生买卖义务，不扣资金或库存。按明确暂定条件生效，逐项记录买卖方、商品、数量、价格及履约状态，库存与资金从各企业独立结算。失败不应留下单笔部分扣款/货物转移。
- 玩家身份与权限必须明确；若市长选举尚不存在，可使用测试或演示场景验证市长专属路径，并清楚标注，不能将玩家无条件当成市长或声称完整政治系统已实现。

### E. 玩家通知与人口图表

- 在现有顶部 UI 正下方放置通知小图标；有通知时不自动打开详情，玩家点击后打开可拖动、可关闭的窗口。按个人、有关企业、玩家担任市长的城市过滤。
- 少量持股只接收分红、玩家有权参与的投票和重大变化；日常经营信息留在企业页面。没有投票权不生成要求该股东参与表决的通知。比例阈值和重大事件标准为可配置演示假设，交付时明确说明。
- 需要玩家处理的事项要清楚可读，不向玩家呈现技术日志、模拟步骤或无关系统信息；不可静默隐藏真正需要处理的存档错误。
- 按已有可信人口数据展示动态饼图，至少包括就业、失业、非劳动力；鼠标悬停扇区浮动并展示名称、人数及比例，数据变化时更新，避免把互相重叠的人口口径相加。提供可读标签、键盘或其他可访问方式，并兼顾减少动画偏好。

## 数据、安全与兼容

- 确定各模块数据所有者；所有跨域事务校验后提交或失败回滚。避免共享状态无约束写入，防循环依赖。保留独立模拟层和可复现种子。
- 为新增状态设计版本化存档和旧版迁移；对初版 `formatVersion 1` 的真实旧存档在隔离目录验证：原存档不被覆盖，读取后原人口、企业、库存、资金、玩家持股及随机状态可解释地保留。新增数据不能偷偷重置原有资产；无法安全推导的数据要有明确迁移策略及失败提示。未来版本与损坏文件必须安全拒绝。
- 不要使用真实地球地图，不要重做世界地图或决定城市内部视角。Rasak 包仍未实际获取和许可核验；不要宣称已经集成，不要绕过下载流程。
- 更新架构及运行指南，写清演示规则、未决定项目和数据权威。不要改变用户已确定的规则，不要把 UI 里的展示当成真实模拟。
