## 2. 人口、就业和收入

- **人口已运行**：每城统计总人口、劳动力、就业、失业及非劳动力，约束总人口 = 就业 + 失业 + 非劳动力。出生死亡采用净增长公式和种子随机扰动；不是逐人模拟。演示劳动参与率为 38%，没有年龄、教育、技能、家庭和完整收入阶层模型。
- **迁移已运行**：以失业率、平均工资、房价、政治支持率等生成吸引力；城市差距、来源失业人口和目的地岗位空缺达到条件时迁移，并同步两城人口。当前仅有统计层级，不模拟搬家、住房分配或迁移费用。政治支持率现有计算方向存在问题，见第 8 节；当前迁移公式实际只使用平均房价，不使用租金或空置率。
- **劳动力已运行但简化**：公共部门先招聘，企业再按固定 ID 顺序从本城失业人口中招聘；企业需求下降时一般每月最多裁员 8%，劳动力总量不足时另有强制调整。岗位按固定比例分配管理、生产、销售和研发；不是按技能、职位资格或工资竞争匹配。
- **工资和收入部分运行**：企业工资按人数乘企业工资率，公共部门类似；有个人所得税、失业补助及非劳动力转移支付。企业现金不足时可能产生本月欠薪，但无完整的工资谈判、家庭账户、储蓄及债务模型。

## 3. 企业与生产

- **企业部分运行**：每家有城市、商品、工资、员工、岗位需求、现金、债务、库存、产能、生产利用率、收入和成本；按规则计算税、利息、还债、股息和产能调整。
- **自动经营简化**：经营决策使用库存、市场未满足需求、现金等固定规则。注释和设计还意图使用上月销售，但执行顺序会先清空数据，实际未生效，见第 8 节。利润和库存触发的小幅扩张/收缩不是完整的资本投资或建设系统。
- **生产已运行但约束不足**：按目标产能和配方消耗库存、生成商品；原料不足会限制产出。当前产出函数没有直接按现有员工数限制产出，零员工仍可能生产，见第 8 节。能源配方无材料投入，是明确演示简化；不可据此宣称已完整实现劳动、设备和资源约束。
- **岗位**：企业员工岗位固定分为管理 8%、生产 76%、销售 10%、研发 6%，按整数分配；这不是独立的管理、销售或研发人员行为模型。
- **企业生命周期未实现**：没有玩家创办企业、完整经营控制、破产清算、并购和动态进出行业。

## 4. 商品、消费和市场

当前共有 8 种演示商品：

| 类别 | 商品 |
| --- | --- |
| 居民消费品 | 食品、成衣、日用品 |
| 企业生产资料 | 谷物、纤维、布料、金属件、能源 |

配方示例：食品消耗谷物和能源；成衣消耗布料和能源；布料消耗纤维和能源；日用品消耗金属件和能源。

- **居民消费已运行但为城市汇总模型**：就业、失业和非劳动力人口按不同固定权重形成需求，再依据上月居民收入、96% 演示消费倾向和价格弹性计算有效购买需求。不代表已经实现每个家庭的收入、储蓄、购物偏好或收入阶层。
- **企业采购已运行**：根据生产配方和库存缺口，先本地购买，不足时可跨城补货。各卖家逐笔成交，可部分满足需求；采购前可能借入资金，即便最终无供应，规则待决定。
- **城市市场已运行**：各城市各商品有价格、供应、需求、实际本地成交、未满足需求、跨城进口和库存统计。卖家按报价等规则撮合；企业自用原料预留。价格按供需和库存简化调整，有上下限和单月变化约束。市场库存统计与企业库存有关，不能理解成已实现独立的实体仓库与完整订单簿。
- **局限**：没有丰富的替代商品、品质、个体消费偏好、详细服务业或成熟市场预期；演示价格公式和参数有待设计与平衡。

## 5. 贸易、金融和财政

- **跨城贸易部分运行**：8 条初始长期合同加区域市场补货，会实际转移企业库存和资金并记录贸易流。区域补货使用按距离计算的价格加成，但没有运输实体、运输时间、运力、损耗或完整物流费用核算。
- **区域外需求为演示机制**：区域外买家按简化规则购买部分消费品，带来区域外资金；不代表已有国家、真实贸易伙伴或完整进出口系统。
- **企业信贷为演示机制**：可按基础工资额借营运资金、付息和还债；特定条件下减免部分债务并注入资金。尚无银行主体、存款、银行资产负债表或真实破产制度。融资与采购的关系待决定。
- **财政部分运行**：城市取得个税和企业税收入，支付公共工资及一定福利；财政可出现赤字，福利受资金限制。没有完整公共预算、债券、税率政策操作或公共服务供给系统。
- **游戏 GDP 已运行但简化**：按企业生产的产出价值减中间投入价值汇总，城市结果下限为零；不含完整公共服务核算。属于游戏指标，不等同现实国民经济核算。

## 6. 科技、政治和房地产

这三个系统目前主要是初始状态展示，不是完整机制：

- **科技**：每城有固定等级、研究点及生产率系数；系数参与初始产能和岗位需求计算。没有研发投入、技术升级、扩散或技术树。
- **政治**：展示支持率、执政党名称和选举倒计时；支持率参与迁移吸引力计算，但存在方向问题。没有实际政党活动、选举结算、政策制定或玩家参政。
- **房地产**：展示均价、租金指数和空置率，其中平均房价参与迁移吸引力计算；没有土地/房产买卖、住房供需、房租形成或城市建设。

## 8. 盘点发现：影响后续机制设计的实现问题

以下为 2026-11-01 对指定提交进行的代码检查和定向复现结果，尚未修复：

1. **企业决策丢失上月销售**：月结先清空企业 `lastMonth`，后执行读取上月销量和产量的经营计划。控制其他条件、改变上月销售后，下一期利用率仍一样，导致原本依赖上月销售率的调整不生效。需要区分上期记录与本期累计；修复时同时审查跨城出口在销量中的统计口径。位置：`src/simulation/core/simulation.ts`、`src/simulation/companies/planning.ts`。
2. **零员工仍可产出**：生产上限直接从产能和利用率开始计算，再受原料约束，没有按当期员工数量直接限制。定向调用中，员工为 0 的能源企业仍产出 349,608.96 单位。应设计并实施员工、技能、设备与产能的明确约束，同时保护现有守恒规则。位置：`src/simulation/production/production.ts`。
3. **政治支持率迁移方向疑似反向**：其他条件不变时，支持率从 40 提高到 80，迁移吸引力从 -18.92 降至 -22.12。当前系数前为负号；需要确认支持率含义后调整并测试。位置：`src/simulation/population/population.ts`。
4. **自动存档读取错误可能覆盖原文件**，以及 **无供应时采购前借款的规则待定**：详见共同开发计划的当前问题。

## 9. 建议讨论顺序

建议先修存档保护与第 8 节中已复现的基础问题，再从人口—就业—工资—消费—企业生产—市场—GDP 的一条链入手，逐个决定玩法与数据口径。科技、政治、房地产及投资控制权可在用户决定优先级后分别设计。该顺序是建议，不是新批准的设计。
