## 2. 企业自动经营

- 三种经营风格【暂定】：`growth`（扩张）、`steady`（稳健）、`return`（回报）。风格由企业 ID + 行业确定性分配，旧存档迁移时同样确定性补齐，不改变资产。
- 企业 AI 读取：上月产量/销售/出口、成品库存、本地未满足需求、现金、工资（含补贴后的有效工资）、连续亏损月数、政策状态；输出：利用率、岗位需求、扩产投资、价格倾向，并记录玩家可读的决策原因（`company.ai.lastPlan` / `lastDecision`）。
- 相同形势下不同风格给出不同计划（测试覆盖）；所有意图仍受现金、劳动力、库存、产能和财政预算校验，不绕过权威数据。
- 融资仍走既有证券/融资要约系统；企业买方买入股票必须有投票权等既有规则未改动。董事会、股东与经营控制权仍分开，AI 不修改治理权利。

## 3. 企业成立与倒闭

### 3.1 成立

- 三类创办主体：居民投资群体（同城最多 3 个群体联合）、现有企业（限本城）、城市政府。资金与股份全部来自出资人：居民实体现金 / 企业现金 / 市财政；新企业获得等额现金，**不凭空产生资金或人口**。
- 新企业初始：1,000,000 股（80% 投票权 + 20% 仅分红，均发给出资人，按出资比例）、产能 = 资本 ÷ 500、0 员工、岗位需求按产能生成；市政府持股的持有人类型为 `city`（新持有人类型，已接入证券、治理、存档与不变量校验）。
- 数量限制【暂定，可配置】：每城 16 家企业、每投资者群体 3 家、每现有企业 1 家、每城政府 1 家、同一城市自动创办冷却 4 个月、最低资本 250,000（初创扶持可降低 30%）。投资者人数上限：一个创办辛迪加最多 3 个居民投资群体；居民群体资格与代表人口、现金相关（不新增人口）。
- 成立记录 `lifecycle.foundings` 保留出资人、金额、股份、财政扶持、时间与说明；失败路径（资金不足、数量上限、重复创办）明确返回原因且不改变资产。
- 自动成立：市政府/居民群体在有明显未满足需求、出资能力与冷却条件满足时每城每月最多 1 家。

### 3.2 倒闭

- 判定【暂定】：经营月龄 ≥ 6、连续亏损 ≥ 4 个月、现金 < 0.25 个月工资、且已无可用信贷；企业纾困政策有余额时暂缓。也可由显式命令清算（测试与后续玩家操作）。
- 清算顺序【暂定，最小完整流程】：现金先偿还债务（不足部分记为减免并留痕）→ 剩余现金按持股比例分配给股东（取整差额归最大股东）→ 库存按账面注销并记录数量与估值（不产生现金、不凭空发币）→ 员工释放并同步城市人口（变为失业）→ 既有协议相关未完成条目置失败、参与方记录拒绝 → 董事席位/控制权/订单/融资要约/股份类别与持股记录清理；该企业提出的或关于该企业的议案被移除并在清算记录中说明；倒闭企业作为其他企业股东持有的股份按其在倒闭企业中的持股比例转给其股东（发行量守恒）。
- `lifecycle.liquidations` 记录：员工数、现金、债务、已偿还/减免、股东分配明细、注销库存明细、受影响协议、原因与说明。重要事件按既有通知规则发给利害关系持有人。
- 明确不实现：完整公司法、破产法院、资产拍卖、债权人协商、遣散费与优先权顺序；这些仍是待用户决定的规则。

## 4. 候选人、领导人与政府政策

- 每城 3 名候选人【暂定】，姓名/党派/倾向/重点行业由城市 ID 确定性生成；领导人被动属性 = 1 个重点行业（匹配行业 +6% 生产率，有上限）+ 7 个政策领域倾向（0–1，影响 AI 选政策权重与对应政策效果放大，最多 +20%）。
- 选举【暂定】：任期 24 个月，到期自动选举；候选人按支持度 + 执政表现 + 确定性规则排序。玩家可支付 60,000 信用点参选（费用进入市财政，失败不退），胜负由财政/失业表现决定；也保留明确标注的“市长演示身份”入口，直接验证玩家市长路径。玩家在任时没有 AI 领导人被动加成。
- **用户已确认规则**：玩家当市长时政策由玩家选择，AI 不代选。实现：`autoSelectPolicies` 对玩家市长城市直接跳过并记录“等待玩家选择”；玩家通过界面逐项选择政策并可**自行填写预算**；非玩家政府按城市弱项（失业、企业困难、产业、科技、贸易拥堵、民生、财政）+ 领导人倾向 + 财政承受力（保留至少 1 个月公共工资）选择政策并记录原因。
- 财政：个税、企税、公共工资、福利、政策支出、交通建设/维护、参选费用、清算相关记录全部写入 `world.fiscal.ledger`（来源、金额、城市、政策/企业引用、tick）。支出不得超过可用财政余额；不足时按明确规则拒绝启动或按可用余额支付，并在界面/日志告知。

## 6. 公路、铁路与交通容量

### 6.1 网络

- 城际：每对城市各有公路/铁路线路【暂定初始公路 1 级、铁路 0 级】，等级 0–4；容量 = 等级 × 每级容量（公路 1,200,000、铁路 3,600,000 货物单位/月）。政府出资开工，建设需要 3/5 个月，建成后等级与容量提高；每月维护费按建设成本比例从财政支付。
- 城内：每城道路/铁路等级 0–3，配送容量 = 道路 2,400,000/级 + 铁路 6,000,000/级；上月“本地成交 + 进口”配送需求决定本月配送效率（容量/需求，最低 0.55），实际限制本地市场可配送量。
- 不做交通私有化；没有私人线路、私营运输企业、逐车/逐路线模拟、客运/通勤与延误。

### 6.2 容量结算（【暂定】方案；用户已确认的原则已遵守）

用户已确认：容量不是成交数量/交易额上限；超容量只按比例减少卖方该笔跨城收益；不得在交易之外从企业账户额外扣钱或另收惩罚费；容量提高后同样需求下惩罚应减轻。

实现：

1. 成交时买方按成交价全额付款并取得货物；卖方**暂不入账**，该笔销售进入 `transport.pendingSales`。
2. 月末按“城市对”汇总全部跨城路径（企业长期合同、政府牵头协议、企业跨城采购、居民跨城购买）的需求，统一计算：
   - `overloadRatio = max(0, demand − capacity) / demand`
   - `penaltyRate = min(0.5, overloadRatio × 0.6)`；容量为 0 且需求 > 0 时取最大 0.5。
3. 卖方实际所得 = 该笔成交额 × (1 − penaltyRate)；差额 `capacityLoss` 记入交通结算记录，**不进入任何主体收入**（不是政府/运输方罚金）。
4. 买方付款不变；买卖双方账目恒等：`grossValue = sellerProceeds + capacityLoss`；不额外从卖方现金扣款，不产生负数。
5. 跨城贸易支持政策存在时，财政按损失向卖方补偿（预算封顶），补偿单独记账；容量规则本身不变。
6. 城内配送效率用于本地采购上限，运输货物数量守恒（未配送部分留在卖方库存）。

其他暂定：需求以“货物单位/月”计，按城市对合并计算、不区分方向；无按商品拆分；未收运费；无运输时间/在途/损耗；买方付款与卖方所得的另一种方案（买方少付）未采用，因为用户尚未决定。

### 6.3 验证

`tests/transport.test.ts`（9 项）：

- 零容量：100 单位仍全额成交，罚率 0.5，卖方所得 = 成交额 × 0.5，买方付款不变，库存守恒，无额外扣款。
- 容量等于需求：罚率 0，卖方全额所得。
- 容量高于需求：罚率随容量提高而下降；2 倍容量时罚率 0。
- 2 倍容量需求：交易全额成交，未被截断。
- 政府建设后容量提高，同样 100 单位需求罚率降为 0。
- 同一城市对的企业采购 ×2、居民跨城购买、政府协议、长期合同五条路径共享同一需求/容量/罚率；逐笔账目恒等；卖方现金总和等于所得总和。
- 城内：上期配送需求 2× 容量、效率 0.55 时，本地可配送量按 55% 限制；城内升级建设由财政出资，建成后容量提高。

## 11. 暂定规则清单（需要用户后续决定）

1. 企业风格种类、系数、切换条件；是否允许玩家直接下达经营命令。
2. 企业创办上限口径与数值（固定/随人口动态）、投资者人数、政府创办权限与预算上限。
3. 倒闭判定阈值、清偿顺序、库存处置（注销/拍卖/折价）、债务减免与债权人权利、遣散费、重组。
4. 候选人产生方式、选举资格/任期/政党、玩家参选成本与胜负规则、领导人属性作用范围与离任处理。
5. 政策预算、期限、冷却、叠加规则（尤其新增招聘与稳岗是否可对同一员工月叠加；当前【暂定】为不叠加：新员工当月只计新增补贴，稳岗计既有员工）、政策效果强度与失败可能。
6. 培训/教育/研发/住房/设备的完整机制与数值；当前只是支持政策闭环的最小状态。
7. 交通容量单位与统计范围（城市对 vs 路线 vs 商品）、惩罚公式与上限、零容量处理、买方付款与卖方所得的最终账务、是否收运费、城内配送的计费/时间、客运与通勤。
8. 交通建设时长、维护费、财政不足时的处置、是否允许跨城共建。

## 12. 已知问题与未完成内容

- 桌面 GUI 冒烟未执行（Electron 二进制缺失）；`npm run smoke:mechanisms` 的脚本逻辑已通过独立单元测试，但布局/可拖动窗口/截图需要图形环境复验。
- 仓库没有真实历史存档文件；迁移用结构忠实的降级存档验证，未覆盖用户机器上可能存在的特殊旧数据。
- 企业倒闭没有资产拍卖与债权人协商；库存注销不产生现金；不实现完整公司法。
- 企业 AI 不模拟设备实体、土地、建筑、研发团队；扩产为“按单位产能付费”的最小机制。
- 交通没有逐车/逐路线/时间/在途/损耗/客运；需求按城市对合并，不区分商品与方向。
- 政策数值为原型，可能造成财政长期趋零或企业盈利压力；AI 选政策只做单步评分，不是长期规划。
- 非玩家政府与玩家市长的政策预算都受可用财政限制；财政不足时部分政策只支付部分金额，效果按实际支付额缩放（如补贴人数）。
- 住房只影响空置率/租金指数/迁移吸引力与居民转移收入，不是完整房地产市场；教育培训技能只影响产出上限，不改变职业结构。
- 旧存档迁移后的新企业/候选人/交通为演示初始状态，不代表历史真实情况。
