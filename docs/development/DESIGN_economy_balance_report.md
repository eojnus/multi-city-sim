# 设计稿 B：36 月固定条件经济平衡观察

状态：设计稿（脚本未实现，未提交）。数值口径/指标清单归「数值与数据」，脚本 `scripts/economy-balance-report.ts` 归本岗，
实现依赖的契约字段归「架构师」，业务逻辑归「游戏程序」。
依据：任务书 §5.3 / §八.3、`DECISIONS_v1.md` #6/#8/#11/#12/#19–#21/#22。
基线：`feature/data-tuning` @ `9cef5b5`。

## B1. 目的与边界

- **只做一次**：固定初始条件 + 固定种子 + 36 个月，不做多种子、参数扫描、反复调参（任务书明确要求）。
- **只观察**：脚本只读世界状态；不修改游戏规则、不写用户存档、不进游戏运行时。
- **不能证明整体平衡**：单次观察只说明"该初始条件 + 该种子下发生了什么"；结论必须附样本局限。
- 若政府仍持续恶化、企业异常倒闭，如实报告，不通过隐藏数值/删事件/跳过计费掩盖。
- 读者：秘书处、架构师、验收。数字可直接引用进交付报告；报告章节由本岗写"数值章节"。

**试跑可行性（只读干跑，现有基线 9cef5b5，未接债券/消费贷机制）**：36 次 `tick()` 约 1.04 s，不变量违规 0 次。
同一固定条件下已看到明显问题，正式脚本落地后必须如实记录、不修饰：
岚港 GDP M1 218.6M → M12 47.8M → M36 27.3M；财政 +60M → M36 −422.8M；
铁谷财政 M36 −247.4M；企业 20 → 38 家（累计倒闭 6、成立 27）；银行违约合同 123 笔（违约未偿占比高）。
这说明"只看第 1/12/36 月财政与负债"不足以说明问题，脚本必须同时记录 GDP 轨迹、企业退出、银行违约与居民消费缺口。

## B2. 固定初始条件（必须可复现）

| 项 | 取值 |
| --- | --- |
| 世界创建 | `Simulation.create(DEMO_CONFIG)`（新世界默认初始化，不读用户存档） |
| 种子 | `DEMO_CONFIG.simulation.seed = 20261101`（固定，不提供 --seed 覆盖，避免"报告可复现"被破坏） |
| 起始时间 | 2026 年 1 月，tick 0 |
| 月数 | 36（可传参缩短，默认 36） |
| 玩家操作 | 无（玩家不担任市长、不下达经营命令、不注资、不买卖） |
| AI | 默认政策/自动经营/托管全开，不做人工干预 |
| 世界改造 | 无（不 mock、不注入资金、不改城市参数） |

复现校验：同种子连跑两次，脚本关键数值应逐位相同（脚本支持 `--repeat` 自检，默认关闭；报告附"两次一致"结论）。
实测依据：3 次 tick 约 194 ms（本机），36 月预计 ≈ 2–3 秒，可在每次交付前重跑。

## B4. 采样点与输出格式

### 采样

- **交付断面**：第 1、12、36 个月末（任务书硬要求）。
- **内部逐月序列**：1–36 每月记录上述指标（用于趋势、自动异常判定、CSV 导出），默认不全部打印（太吵），只打印世界级紧凑表 + 3 城断面。

### stdout 结构

```
=== 经济平衡观察：固定条件 36 个月 ===
[参数] 种子 20261101；起始 2026-01；配置 DEMO_CONFIG(演示参数 v0.4)；玩家无操作
[初始] 三城财政/企业数/居民资产/企业可认购上限（与 A 稿开局 GDP 估计并列）

[A. 三城断面] 第 1 / 12 / 36 月 × {财政余额、当月收支、总负债、债务/GDP、预警档位、
    企业数、当月成立/倒闭、居民消费预算/实际、消费贷余额/逾期、GDP(当月/12月合计)}
    每格给 M1 / M12 / M36 与两段变化（M12−M1、M36−M12），负号明确

[B. 世界逐月表] 36 行：月 | 世界GDP | 就业 | 企业数 | 成立 | 倒闭 | 居民消费 | 消费贷余额 |
    财政总收入 | 财政总支出 | 总负债 | 平均债务/GDP | 不变量违规

[C. 企业异常 Top] 亏损最大 / 现金最紧 / 库存最高 / 当月倒闭 各前 5

[D. 债券与银行] 发行/成交/未售/票息/还本/垫付；贷款结构；违约与逾期

[E. 会计利润 vs 现金流] 全局与分城：利润、近似经营现金流、差额、融资净额、原因注记

[F. 异常清单] 按 B5 判据自动列出的条目（含月份与主体）

[G. 样本局限] 固定条件/单种子/36 月/无玩家操作/模型口径近似/不能证明整体平衡
```

### 格式约定

- 金额：整数信用点（千分位）；比率：2 位小数；百分比：1 位小数；负号保留。
- 每个数字可追溯到字段（报告附录给字段映射表，B3 即该表）。
- `--json`：输出同结构的 JSON（机器可读，供验收/图表）；`--csv <path>`：逐月 × 城市长表。
- 失败处理：某月 `tick()` 返回 `ok=false` 时，打印错误、已完成月数与已采样数据，退出码 1。
- 不写 `artifacts/`（归验收）；CSV 路径由调用者指定，默认不写文件。

## B5. 自动异常判据（观察口径，不是游戏规则；只报告不改世界）

| # | 判据 | 阈值（首版观察值，可调） |

## B11. 已知限制：破产后 AI 政府发债不再恢复（块6 探针发现，v0.7 不改）

**现象**：岚港 M20、铁谷 M30 破产清算后，36 月内两市再未发行任何债券；财政赤字改由银行普通贷款补足（岚港 259,770,477、铁谷 102,566,987），M36 负债率分别回升至 73.0% / 20.0%（来源：块6 探针 `9bf24d2`，`docs/development/reports/economy-probe-block2.json` 的 `probe.bankruptcies` 与 `probe.financingByCity`）。

**根因（当前实现行为，不是 bug）**：
1. 月结时财政余额为负 → `borrowForGovernment()` 把赤字转为政府银行贷款（`config.government.loan`：月息 0.5%、24 期等额本金、`nextDueTick = startTick + 1`）。
2. AI 自动发债的"禁借新还旧"判定 `hasDebtServiceDueThisTick()`：只要存在任一政府贷款 `nextDueTick <= tick` 即返回 true。
3. 政府贷款每月都有到期分期 → 该判定恒真 → AI 发债触发条件永不满足。
4. 结果不是"停止融资"，而是**债券被银行贷款完全替代**：岚港破产后 16 个月新增贷款 259.8M，债券 0 期。

**结论**：登记为正式已知限制，**v0.7 不改**（AI 发债禁止借新还旧是既定规则 #29，贷款月供阻断发债是规则叠加的结果）。交付报告 §8 与块6 设计稿 D11e/D11f 同步记录；若块3/验收认为破产后应允许"新市长重新发债"，需作为新决策提出，不在数值段解决。

**观察风险**：岚港 M36 负债率 73.0% 仍在上升通道，窗口延长可能在 M45+ 二次破产；同期银行垫付 788.2M 全额核销、无资本充足口径（同为已登记已知限制）。
