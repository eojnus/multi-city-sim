## 讨论中的游戏内容

### 企业 AI 自动经营

**用户目标**：讨论值得加入哪些企业 AI 自动经营内容。企业需要能在持续运行的世界中自主经营，并与人口、商品市场、股权、贸易和政治相关机制相互影响。

**已确认的相关项目原则**：企业是独立经营主体；普通企业可在没有玩家逐项操作时自主运行。玩家持股不自动等于控制权。政府可牵头多企业跨城贸易协议，企业可以拒绝参加。企业与人口投资、股票、董事会等已确认方向详见开发计划；本次讨论不改变正在开发的任务范围。

**本次用户确认**：不同企业应当有不同的经营目标和风格；世界中应有新的企业成立、旧企业倒闭的机制。企业风格种类、成立条件、倒闭判定及后续处置仍待设计，不能把候选示例当成固定规则。

**企业创办与数量限制——用户进一步提出**：新企业的创办应与人口机制结合；现有企业和城市政府也可以参与创办新企业。需要对投资者数量、企业数量、现有企业及城市政府能够成立的企业数量等方面设置限制，避免无限增长。各类限制的确切对象、口径、计算方式和数值尚待讨论；投资实体是群体，不应自动等同于一个自然人投资者。

**供讨论的数量限制划分（建议，未确认）**：

- 人口及投资者：城市居民中的潜在投资者数量与可用资金从人口、收入和财富形成，不凭空增加；人口与投资者之间的统计口径需单独定义。
- 城市内企业：结合人口、就业、消费、市场机会及其他城市条件，确定城市能够容纳或形成多少企业；如何计算需讨论。
- 现有企业创办：已有企业能否成立其他企业，以及数量、资金与管理条件如何限制，需要定义，不能误把现有企业总数等同于可创办的数量。
- 政府创办：城市政府能成立哪些企业、数量和预算受到什么限制、是否可与其他投资者共同成立，均待设计；不能无限创办或凭空出资。
- 用户尚未决定限制使用固定数量、随城市条件变化，还是两者结合；也尚未确定人口中的投资者资格、单人持有多家公司、企业倒闭后额度如何变化。

**讨论建议，尚未确定**：

- 让企业围绕现金、员工、库存、商品价格、市场需求和已有合同自主制定招聘、采购、生产、定价、销售与财务计划；实际执行仍受资金、岗位、库存、产能和协议约束。
- 对资金不足、原材料短缺、销售不佳和市场扩张等情况，考虑借款、降产、调整招聘、寻找贸易伙伴、融资或分红等决策；先设计经济后果与边界，不应自动免除一切经营风险。
- 为不同企业考虑不同经营倾向，例如稳健、扩张或重视分红；它们仍遵守同一套经济规则，倾向和判断依据可变化，不应被固定为无条件标签。
- 区分经营层、董事会和股东的权限；玩家有经营控制权时可按授权影响决策，但仅持有少量股份不意味着能直接操纵企业。具体权限和投票机制待讨论。
- 向玩家展示能理解的决策原因，例如原材料紧缺导致减产或库存积压导致调整生产；日常经营信息放在企业页面，只对符合已确认条件的重要事件发送通知，不显示技术日志。
- 建议从可解释、可复现的规则和少量参数开始，之后再评估更复杂的策略，不为每家企业依赖外部聊天模型实时决策。

**待决定**：

1. 不同企业的经营目标和风格如何形成、变化，如何在长期成长、稳定生存与股东回报之间取舍？
2. 企业严重亏损或资不抵债时，允许什么形式的融资、重组、停业和破产？政府或其他投资者能否救助？
3. 哪些决定由经营层自主做，哪些必须经董事会、股东或政府批准？
4. 玩家取得经营控制后，能够直接下达哪些命令，企业管理层在无命令时如何继续运转？
5. 企业扩大产能是否必须支付资金、获得设备、土地或建筑，以及建设的时间和条件？
6. 企业多久进行一次决策，短期风险与长期规划怎样衔接？
7. 如何根据用户已确定的身份通知规则定义企业的重要事件，不把日常经营刷成大量通知？
8. 投资者数量、各城市企业数量、现有企业可成立的其他企业数量及政府可成立的企业数量，分别按什么规则与口径限制？

### 政府政策、候选人与领导人特性

**用户目标与已确认方向**：政府可以推出政策刺激经济。游戏需要准备较多候选人，他们在多个领域有不同影响；每个领导人具有自身的被动属性，可刺激不同行业和发展方向。政府根据城市目前的弱项以及领导人的倾向，推出对不同方向有不同加成的政策。

**用户进一步确认**：玩家成为市长时，政策由玩家选择。政府要有税收系统，并可通过分配财政资金推行政策。例如失业率高时，政府出资为企业雇佣人口提供补贴；补贴需要在机制上影响企业的招聘意愿。企业 AI 的基本趋利避害应合理，不能仅仅展示补贴而不改变行为。税收种类、拨款方式、补贴适用范围和计算公式尚未确定。

**用户确认补充**：招聘补贴既覆盖新增雇佣，也覆盖继续雇用员工、维持岗位。两类补贴的对象、期限、金额以及同一岗位能否叠加仍需设计。用户确认将以下政策全部纳入后续游戏规划；各政策的参数与效果需要进一步细化，尚不代表当前开发分支已经实现。

**用户确认纳入的政策清单（具体细则待设计）**：

| 方向 | 政策 | 预期作用与机制联系 |
| --- | --- | --- |
| 就业 | 新增招聘补贴 | 补贴符合条件的新增雇佣，降低企业新增用工成本，影响招聘意愿。 |
| 就业 | 稳岗补贴 | 对符合条件的现有岗位给予支持，降低保留员工的成本，影响裁员决策。 |
| 就业 | 职业培训 | 为居民培训提供资金，使其未来更有机会满足岗位需求；依赖技能和培训机制。 |
| 就业 | 公共岗位计划 | 使用财政资金设立公共岗位，吸纳符合条件的居民并承担工资等成本。 |
| 企业 | 初创扶持 | 资助符合条件的新企业或创办者，影响创业门槛和企业成立；不能凭空产生其他资源。 |
| 企业 | 企业纾困 | 支持符合条件的困难企业，影响其资金与经营风险；不能保证所有企业都会存活。 |
| 产业 | 设备与扩产补助 | 补贴符合条件的设备或扩产投资，影响企业的投资决策；依赖设备与建设机制。 |
| 产业 | 重点产业扶持 | 对选定行业提供扶持，具体效果、资格与资金用途待设计。 |
| 科技 | 研发资助 | 支持企业或研究机构研发，影响研发投入与成果；依赖研发机制。 |
| 科技 | 教育投入 | 为教育和人才培养投入资金，逐步影响劳动力技能；依赖教育与人才机制。 |
| 贸易 | 跨城贸易支持 | 支持企业开拓跨城市场或运输，影响可承担成本与贸易意愿；企业仍可拒绝协议。 |
| 贸易 | 交通基础设施投资 | 建设或改善交通联系，影响长期运输能力或成本；依赖建设和物流机制。 |
| 民生 | 失业救助 | 对符合条件的失业居民提供转移支付，影响财政和居民可支配收入。 |
| 民生 | 住房支持 | 支持符合条件的住房需求或住房供给；具体方式未定，依赖住房机制。 |
| 财政 | 税收调整 | 在具体权限内调整税种或税率，影响居民、企业和政府收入；税种、授权和边界待设计。 |

政策不能仅改变展示数字：应经过财政、居民、企业、劳动力或市场的相应机制生效。不同政策的资金来源、目标人群、期限、预算限制、补贴叠加和评估口径待设计。政策应受到实际资金和资源约束，政府不能凭空创造员工、货物或财政资金；政策未必必然成功。

**讨论中的建议，尚未确定**：

- 候选人和领导人可以在产业、就业、财政、科技、公共服务或贸易等方面有不同倾向；具体领域、角色数量、属性和产生方式待用户确认。
- 被动属性与政府政策应分别记录：领导人特性是其个人影响，政策是政府选择实行的措施；作用对象、上任和离任的生效方式、是否叠加等仍需设计。
- 政府可观察就业、财政、产业供需等城市指标，识别弱项，再结合领导人倾向比较可选政策。指标定义、决策流程和政策效果均待确定。
- 税收和财政资金分配已由用户确定为政策体系的一部分；具体税收种类、预算分配方式、执行时间、持续时间与副作用尚未确定。
- 关于招聘补贴，建议企业依据实际资金、工资与补贴、岗位需求、生产条件和预期销售收益综合判断招聘，不应因为有补贴就无条件创造员工或无视经营约束。补贴对象、金额、期限和企业如何使用资金待讨论。
- 政策需要通过人口、财政、企业、商品市场、科技等现有数据权威生效，不能凭空创造资金、人口、员工或无来源的商品。真实影响应在玩家可理解的界面中展示，不显示无关系统信息。

**待决定**：

1. 候选人从哪里产生：预设、程序生成，还是两者结合？是否独立于玩家参与选举？
2. 领导人被动属性在什么条件下生效、任期结束后如何处理？影响是否应受城市基础条件约束？
3. 政府怎样定义城市弱项，如何在弱项、领导人倾向和其他目标之间取舍？
4. 玩家市长选择政策的具体权限、提出及撤销流程如何设计？非玩家领导人如何自主选择？
5. 税收种类、财政拨款方式、政策实施时长、冷却、持续期限及副作用如何设计？
6. 政策与领导人加成如何叠加，如何避免无上限增长或绕过资源约束？
7. 各城市候选人、领导人及政策与选举、政党、城市财政和企业之间的关系如何设计？

**当前状态**：现有原型的政治主要为展示，尚不能视为已经实现选举、政策或领导人自动施政；本主题与正在开发的机制任务分开讨论。

### 城市内部与城际交通

**用户确认方向**：加入交通系统，分为城市内部交通和城际交通；交通会影响贸易的收益率。具体交通方式、参与主体、计算方式和建设权限尚需讨论。

**用户进一步确认**：首批先做公路和铁路；其他交通方式留待后续讨论。公路和铁路在城市内部与城际交通中如何分工、具体建设和运营规则仍待设计。

**用户确认运营方向**：当前阶段交通运营由政府主导，不做交通私有化。公路、铁路设施的建设、维护和交通服务运营以政府为主，不把私人拥有交通设施或私营运输企业作为当前设计方案。企业作为货运服务使用者参与贸易；收费标准、具体财政安排和职责分工仍待设计。

**用户确认城际容量机制**：城际交通具有运输容量，并随着交通网络建设逐步提高。容量不是交易额或成交量的硬上限；当运输需求超过容量后，对企业将商品出售到其他城市取得的贸易收益按比例施加惩罚，而非禁止超出部分交易。贸易收益指这类跨城销售的所得，不是整个企业所有业务的利润。扣减表现为该笔贸易所得减少，是销售企业少获得的收益；**不得在交易之外再从企业已有现金中额外扣钱，也不额外收取惩罚费用**。具体如何衡量运输需求、容量与惩罚比例，以及与买方付款一致的账务记录，仍需设计。

**讨论中的建议，尚未确定**：

- 城市内部交通连接企业、居民区、仓储以及城际交通节点，可影响本地配送成本、时间、效率，亦可讨论通勤与就业的关系；不能默认所有路径和交通方式已确定。
- 城际交通连接城市与贸易路线；距离、路线状况、运输方式、通行能力和运输时间可影响物流费用与交付。首批交通方式为公路和铁路；水运等其他方式暂不确定。
- 对一笔跨城交易，可分别考虑出发城市的本地运输、城市间运输和目的城市的本地运输；成本应按双方协议归属到具体企业或其他付款主体，避免重复扣除；收益率基于商品收支和实际承担的成本计算。
- 运力不足对城际贸易按用户确认的规则惩罚收益，不将运输容量直接作为成交量上限。若未来讨论延迟、中断或损耗，应与该规则保持一致；货物的来源、运输中状态、到货与损耗必须可追溯，不能凭空复制或丢失。
- 交通建设、运营、维护和财政投资可能与政府政策、企业和居民需求有关；建设和费用规则需要进一步确定，政策不能凭空生成基础设施。

**待决定**：公路和铁路在城内与城际如何分工；运费和责任由谁承担；乘客交通与货运如何联动；建设是否耗时、是否有拥堵与中断；玩家有哪些交通管理权限。

**当前状态**：现有原型仅有跨城交易的简化价格加成，不等于已有完整城内交通、运力、运输时间或物流运营。此为独立设计讨论，不改变正在开发的机制任务。

#### 公路和铁路的建设与运营（讨论中）

**用户讨论重点**：确定公路与铁路如何建设、运营，并与企业贸易发生联系。首批公路与铁路已确认；以下只是候选建议，未被视为用户决定。

- 可将交通设施的建设与维护，与车辆、货运或客运服务的运营分别核算；当前按用户确认由政府主导，具体政府部门、城市间协作和价格权限待定。
- 候选道路模型：政府投资建设及维护道路，并主导运输服务；政府是否收取道路相关费用、具体车辆是否逐个模拟均待定。
- 候选铁路模型：由政府主导铁路线、车站与运输服务，明确跨城市建设、维护和运营责任；资金与服务规则待定。
- 运费、运输时间、可用运力和拥堵等可影响贸易结果。货物运输从原企业出库、在途、到达入库或依法设计的损耗，应有连续可追溯记录；明确买方、卖方、运输方与政府之间各项费用的实际收付，避免重复扣费或无来源收入。
- 基础设施需要明确资金、建设时长、运营收入和维护成本；客运是否纳入首版及其与居民通勤的关系尚待确定。
- 初期可考虑以路线、运力和货运订单作统计模拟，不必逐辆跟踪；是否采用该简化需结合玩家期望继续讨论。
- 在玩家界面用清晰信息展示可用路线、运输成本、时间及对利润的影响；不要将内部模拟调试信息当作玩家事件。

**待决定**：政府内部与跨城市的职责分工；货运和客运的优先级；容量单位及统计范围（城市间或路线等）、需求如何折算、超载比例与收益惩罚公式、无连通路线或容量为零的处理、企业损失如何在账目中记录；收费方式、拥堵和风险；是否模拟逐车路线。

## 实现现状（2026-11-02，外部交付待验收）

以下为实现状态，不改变上文“已确认/待决定”的划分；未确认细则仍以【暂定】标注，最终规则待用户决定。

- **企业自动经营**：三种风格（扩张/稳健/回报）会改变招聘、生产、扩产与定价计划，并把原因显示在企业页面；资金、劳动力、库存、产能与补贴预算仍由权威模块校验。
- **企业成立与倒闭**：居民投资群体（可联合）、现有企业与城市政府均可按条件创办；数量、投资者人数与政府创办数有可配置上限。倒闭会处理员工、现金、债务、库存、股份与协议，并保留成立/清算记录；库存按账面注销、债务减免与股东分配均留痕。完整破产制度、资产拍卖与债权人程序未实现。
- **候选人与领导人**：每城程序生成候选人，领导人有一个重点行业与七个政策领域倾向；重点行业有上限生产率加成，倾向影响非玩家政府选择与政策效果。选举任期、玩家参选成本与胜负条件是演示规则。
- **政策**：15 项政策全部接入财政流水与真实模拟状态（补贴、培训、公共岗位、创办扶持、纾困、扩产、重点产业、研发、教育、贸易补偿、交通投资、失业救助、住房、税收调整）。玩家为市长时由玩家选择政策并填写预算，AI 不代选；非玩家政府按弱项、领导人与财政选择。
- **交通**：城内/城际公路与铁路由政府建设、维护；城际容量按城市对月度汇总，超载只减少卖方该笔收益，容量提高后同样需求惩罚下降。城内配送效率影响本地可配送量。**验收修复后采用【暂定】“差额退回买方”**（买方净支付 = 卖方实得，不额外扣卖方、不归政府），最终商业规则仍待用户决定；详见验收修复报告。
- **存档**：格式 v4，兼容 v1/v2/v3；旧存档迁移不创造资金，保留人口、企业、库存、现金、股份、时间与随机状态。
- 详细数值、暂定方案与验证证据见 [交付报告 v0.4](../development/DELIVERY_REPORT_v0.4.md)。
