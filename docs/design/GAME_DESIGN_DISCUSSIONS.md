# 游戏机制：后续讨论与设计计划

> 持续维护｜更新日期：2026-11-02
>
> 本文只保留后续需要深化的机制、用户已确认且会约束后续设计的规则，以及尚未决定的问题。已经实现的功能清单、交付和验收记录不再放在这里。
>
> **标记说明**：**已确认**是用户明确认可的规则；**待讨论**列出尚未确定的机制；**设计建议**仅用于帮助讨论，不代表用户已经决定，也不自动构成开发任务。部分机制已有原型，但原型参数不等于最终规则。

[后续开发计划](../development/DEVELOPMENT_ROADMAP.md)负责整理整体方向与协作；已交付原型的具体范围、实现和限制可查阅[交付报告](../development/DELIVERY_REPORT_v0.4.md)。每次形成可开发的决定后，再明确规则、依赖、交互、数据和验收方式。

## 一、总体规划

目前优先讨论经济和城市机制，让人口、企业、投资、政府和交通之间形成能解释的反馈。以下顺序是**设计建议**，可以随讨论调整：

1. 居民收入、就业、消费、储蓄与投资之间的联系。
2. 企业目标、自动经营、融资、创办和退出。
3. 股东、董事会、经营者与玩家的权利分配。
4. 企业间交易、政府贸易协议，以及公路和铁路的经济作用。
5. 政府财政、领导人、政策和城市发展之间的联系。

设计每项机制时，继续明确：谁参与决策、资金和商品从哪里来又流向哪里、玩家能做什么、其他系统如何受到影响、界面向玩家解释什么。优先把已确认规则和待定方案分开。

## 二、人口、就业与居民投资

### 已确认的约束

- 普通居民会参与股票购买。每个城市的居民划分为多个投资实体，由群体参与投资，不为每位普通居民单独创建投资者。
- 投资实体内部明细不需要在玩家界面展示。人口信息使用动态饼状图，鼠标悬停在不同部分时有浮动效果。

### 待讨论

- **人口分层**：按哪些维度划分居民及投资群体，例如收入、职业或财富；同一人口的不同统计不能误加成总人口。
- **资金循环**：工资、福利、税收、消费、储蓄、投资和分红怎样衔接；居民可用于投资的钱如何从实际收入或已有资产中形成。
- **跨城迁移**：居民迁移时，原有现金、股票和分红权如何跟随人口或留在原投资群体；迁移前后人口与资产如何保持一致。
- **就业与技能**：岗位需求、工资、技能、培训和失业如何相互影响；居民是否会因工作与生活条件改变城市。
- **投资行为**：群体在风险、可用资金、股票收益和分红之间如何选择；是否以及如何参与表决。
- **人口展示**：饼图具体展示哪些分类、悬停信息与变化趋势；如何让玩家理解就业和生活水平的变化。

**设计建议**：先确定人口与资金的统计口径，再设计投资偏好和界面。居民投资资金应能追溯到居民，分红也不能同时被当作两笔独立收入。

## 三、企业经营、创办与退出

### 已确认的约束

- 企业是独立经营和交易的主体；不同企业应有不同的经营目标和风格。企业、商品、股份和公司治理应互相影响。
- 世界中应有新企业成立和旧企业倒闭。居民投资实体、现有企业和城市政府都可以参与创办；创办应结合人口，并限制投资者、城市企业、现有企业创办及政府创办的数量。具体口径和数值尚未确定。
- 企业可参与政府牵头的跨城贸易协议，也可以拒绝参加。

### 待讨论：自动经营

- **经营目标与风格**：企业如何形成或改变经营风格；如何权衡增长、现金安全、风险和股东回报。不同风格应遵循共同的资金、库存、员工和产能约束。
- **经营决策**：在需求变化、库存积压、原料短缺或资金紧张时，如何决定招聘、采购、生产、定价、销售、融资和投资；决策间隔和长期规划如何设计。
- **招聘与补贴**：企业怎样结合工资、补贴、资金、岗位需求和预期销售判断招聘或保留岗位；补贴应改变实际决策，不能无条件创造岗位和员工。
- **经营解释**：哪些原因适合展示在企业页面，哪些变化足够重要才需要通知；界面使用玩家能理解的表述。

### 待讨论：创办与数量限制

- 居民投资实体的创办资格如何与人口、财富、投资意愿和可用资金挂钩；“投资者数量”的统计口径是什么。
- 城市企业总量是使用固定上限、随人口和市场条件变化的上限，还是两者结合；不同行业是否共享同一额度。
- 现有企业创办其他企业时，资金、数量、管理能力和持股关系如何限制；不能把现有企业总数直接当成其可创办数量。
- 城市政府的创办范围、数量和预算如何限制；政府能否与居民或其他企业共同出资。
- 企业倒闭或转移后相关名额如何变化；同一投资实体能否参与多家企业。

### 待讨论：困难、重组与退出

- 持续亏损、无力偿债或资不抵债时，融资、缩减经营、停业、重组和破产分别在什么条件下发生。
- 企业退出后，员工、现金、库存、设备、债务、股份和未完成协议如何处理；是否需要资产出售、债权人顺序或其他程序。
- 企业或政府救助的条件、额度和风险如何确定；救助不应保证企业一定存活。
- 扩产是否需要设备、土地、建筑和建设时间；这些资源从何而来。

## 四、股票、融资与公司治理

### 已确认的约束

- 股票分为两类：一类有投票权，另一类只能分红。
- **企业作为买家在股票市场买入的股票都有投票权。**
- 企业融资时，可以针对不同出资方分别决定是否给予投票权，包括分别给予或不给不同企业出资方投票权。
- 玩家持股不自动等于取得企业经营控制权。

### 待讨论

- **股份权利**：有投票权股份的分红权、每股票数、转让后权利和不同类型股份的具体边界；个人在股票市场购买时适用什么规则。
- **融资**：发行条件、定价、谈判、资金用途、对原股东比例的影响，以及现有股东有哪些保护。
- **股东与董事会**：董事如何产生和更换，哪些事项由股东表决、董事会决定或经营层自主处理。
- **玩家权限**：持有少量股份、成为大股东、取得控制权或担任经营者时，玩家分别能查看和决定什么；没有玩家命令时企业如何继续经营。
- **投票与分红**：投票资格如何确定，持股变动对正在进行的表决有什么影响；分红比例、发放时点与企业资金需求如何平衡。
- **政府持股**：政府除创办企业外能否参与融资或购买存量股份；持股决策、财政资金和投票权限如何安排。

**设计建议**：先明确各角色的权限边界，再设计操作入口和 AI 决策，避免把股东、董事和经营者视为同一角色。

## 五、企业交易与政府贸易协议

### 已确认的约束

- 企业各自独立交易、持有资金和商品。跨城交易可以由企业直接进行，也可以由政府牵头，组织不同城市的多家企业参与购买与出售。
- 企业有权拒绝参加政府牵头的协议；政府牵头不等于把所有企业合并成一个交易主体。

### 待讨论

- **协议形成**：由谁提出和签署、如何邀请企业、企业依据什么接受或拒绝，以及多少参与方同意后协议生效。
- **交易条款**：商品、数量、价格、期限、支付与交付方式如何约定；同一协议中多家企业如何分别承担义务。
- **履约与退出**：供货或资金不足时如何部分履行、调整、退出或处理违约；企业倒闭后协议如何继续或终止。
- **政府权限**：政府能提供哪些协调、政策或财政支持；政府在协议中的权利与企业自主权如何划分。
- **收益与风险**：如何在企业页面解释跨城销售所得、原料成本和交通影响；贸易协议与普通企业交易应使用一致的资金和库存口径。

## 六、政府、候选人、政策与税收

### 已确认的约束

- 候选人和领导人应在多个领域有不同倾向；领导人的被动属性会影响行业与城市发展。非玩家政府结合城市弱项和领导人倾向推出政策。
- 玩家担任市长时由玩家选择政策。政府通过税收和财政拨款推行政策。
- 招聘支持既涉及新增雇佣，也涉及维持现有岗位；补贴必须影响企业实际用工意愿。
- 已确认的政策覆盖就业、企业、产业、科技、贸易、交通、民生和财政。政策效果须通过人口、企业、财政等机制产生实际影响。

### 待讨论

- **候选人与选举**：候选人的来源、属性和数量如何形成；选举、任期、玩家参选资格及胜负如何设计。
- **领导人特性**：被动属性的生效条件、作用范围、上任和离任时的变化，以及与政策效果是否叠加。
- **政策决策**：如何衡量失业、财政、产业和贸易等弱项；AI 政府如何在弱项、领导人倾向和财政约束之间取舍。
- **政策预算**：玩家如何分配、调整和撤销预算；政策的实施时间、持续期限、冷却、效果上限和财政不足时的处理。
- **招聘与稳岗补贴**：申请对象、补贴期限和金额如何确定；新增岗位与稳岗能否针对同一员工同时获得支持。
- **各领域政策深化**：培训与教育如何影响技能，研发如何形成成果，扩产扶持如何关联设备与建设，住房支持如何影响住房供需；避免只改变展示数字。
- **税收与财政**：可调整的税种、税率边界、征收对象和资金用途；财政收支、公共岗位和福利怎样影响居民与企业。
- **政策评估**：玩家能看到哪些成本、受益对象和效果变化；如何体现政策可能效果有限或出现副作用。

**设计建议**：将领导人个人特性与政府政策分开设计，明确每项政策的资金来源、目标、执行条件、持续时间及可观察结果。

## 七、城内与城际交通

### 已确认的约束

- 交通分为城市内部交通和城际交通，首批交通方式为公路和铁路；当前阶段由政府主导运营，不做交通私有化。
- 城际交通有随网络建设逐渐提高的运输容量。容量不是交易额或成交量的硬上限；超容量时按比例减少企业**该笔跨城销售所得**。
- 收入减少属于销售企业的损失，**不能在交易之外额外扣除企业已有现金，也不能额外收取惩罚费用**。

### 待讨论

- **建设与维护**：城内和城际公路、铁路的建设权限、资金、工期、维护成本及两城间职责如何分配。
- **运输容量**：容量如何计量、按路线还是城市之间汇总，如何计算需求；无路线或零容量时如何处理。
- **收益结算**：超载比例与收益减少的公式、精度和账务口径。原型暂定把超载差额退回买方；这不是已确认的最终商业规则，仍需讨论。
- **城市内部交通**：配送、企业经营和居民通勤之间如何联系；城内交通是否收费以及由谁承担。
- **公路与铁路分工**：两种方式在容量、成本、覆盖范围、建设时间和适用货物方面是否有差异。
- **运输过程**：是否加入运输时间、在途货物、拥堵、中断和风险；若引入，如何记录货物和资金流转。
- **客运与管理**：客运是否纳入，如何与货运分配资源；玩家作为市长能管理哪些建设和运营事项。

**设计建议**：先确定容量与跨城结算规则，再讨论费用、路线和运输时间；任何新增费用都应有明确承担方，不能把超载收益减少重复扣成另一笔费用。

## 八、事件通知与玩家信息

### 已确认的约束

- 通知区域位于顶部 UI 正下方；出现通知时先显示小图标，玩家点击后打开可拖动的小窗口。
- 通知内容取决于玩家个人、企业持有情况和是否担任市长。少量持股时只通知分红、与其投票权有关的投票和重大变化，日常经营在企业页面查看。
- 通知和其他 UI 只展示玩家需要看的信息，不展示无关系统信息。

### 待讨论

- 哪些企业、个人和城市事件属于重大变化；控股、经营和担任市长时分别接收哪些消息。
- 事件的优先级、合并规则、已读状态、历史记录与跳转位置如何设计。
- 一名玩家同时具有股东、经营者和市长身份时如何避免重复提醒；无投票权时不能收到可参与投票的提示。
- 财政、企业经营和交通造成的重要结果如何用玩家能理解的语言解释，而不刷屏。

## 九、世界地图

已确认世界地图使用虚构的平面地图，初期范围是一小片区域；地图问题暂时不继续展开。以后需要讨论地图时，再决定城市、地形、交通与资源分布如何与经济和政治机制相联系。
