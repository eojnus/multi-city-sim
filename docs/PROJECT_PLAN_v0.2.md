# 1. 项目愿景与核心体验

开发一款以**人口、企业、商品、市场、经济、科技、政治、房地产和城市间贸易**为核心的长期世界模拟游戏。

玩家从一名拥有初始资金的独立投资者开始，进入一个持续自动运行的多城市世界。玩家可以通过投资积累资本、创办或控制企业，也可以参与政治活动并通过选举成为城市管理者。三种发展方向属于同一个连续世界，不是互斥职业，也不是互相独立的游戏模式。

世界中的居民、企业、市场、政党和政府都能够按照规则自主运行。玩家可以影响世界，但不是唯一的决策者，也不需要逐一操纵每个居民或企业。

## 1.1 核心体验

-   在区域战略地图上观察多座城市的位置、领土、产业、经济和贸易关系。
-   进入城市内部，查看有辨识度的 2D 城市街区、道路、建筑和功能区域。
-   通过资本市场投资，积累财富和社会影响力。
-   创办企业、购买股份、通过股东投票或收购获得企业控制权。
-   招聘员工、采购生产资料、组织生产、销售商品、研发和跨城市经营。
-   参与政党与政治活动、支持候选人、参加选举并争取城市公职。
-   观察人口结构如何影响就业、工资、消费、企业经营、股票、房地产和政治。
-   观察城市之间通过商品贸易、运输、人口迁移和产业联系形成区域经济网络。
-   让世界能够繁荣、停滞、衰退、发生短缺或经济危机，并对玩家决策作出反馈。

## 1.2 项目边界

本项目不是以人物动作、战斗或精细建筑漫游为核心的传统
RPG，也不是以逐栋精细建模为前提的 3D 城市建造游戏。

**地图是观察和操作世界的入口，模拟系统才是游戏主体。**

城市内部仍然需要有质量、可辨识的 2D
美术资产，不采用只有几条线和色块的极简地图。但通过复用固定
Tileset、模块化街区和程序化地图组织，避免逐栋制作独立资产和多轮美术调试。

# 3. 玩家身份与玩法

## 3.1 已确认：统一世界中的自由发展玩法

玩家不是开局选择"企业家模式""投资者模式"或"城市管理者模式"。这些身份是同一个经济社会世界中的不同权力和发展方向。

**游戏玩法定位：资本起步、自由发展的社会模拟。**

玩家开局是一名独立投资者，拥有一笔初始资金和基础市场参与资格，但没有预设企业控制权、政府职位、政党领导权或大型社会影响力。

初始资金的具体数值、资产结构和城市选择尚未确定。

## 3.2 资本与投资路径

玩家可以通过资本市场和资产投资积累财富：

-   购买、持有和出售企业股票。
-   投资房地产及其他可交易资产。
-   参与企业融资、增资和股权交易。
-   通过投资组合和跨城市布局积累资本。
-   逐步获得对企业或产业的影响力。

持有股票不自动等于控制企业。控制权还取决于持股比例、股东结构、公司章程、股东投票和其他治理规则。

## 3.3 企业经营路径

玩家可以通过不同方式成为企业家或企业控制者：

-   直接创办一家企业。
-   购买现有企业股份。
-   通过股东投票获得董事会或经营控制权。
-   通过并购、收购等方式取得控制权。
-   与其他投资者合作建立企业集团。

获得企业控制权后，可以逐步参与：

-   企业招聘和岗位设置。
-   员工薪酬和管理层任命。
-   原材料采购、库存和生产计划。
-   商品定价、销售和市场竞争。
-   产品研发、技术投资和企业扩张。
-   跨城市设立分支机构和经营供应链。

具体公司治理制度、控股门槛和股东投票规则待后续设计。

## 3.4 政治与城市治理路径

玩家也可以从经济参与者逐渐进入政治领域：

-   参与政治组织或政党活动。
-   赞助、支持候选人或政治活动。
-   建立政治声望和社会影响力。
-   参与选举、竞选城市公职。
-   在满足制度条件并获得选举结果后成为城市管理者。
-   参与城市财政、税收、产业政策、公共投资和城市规划。

赞助候选人不保证其当选；财富也不自动转化为政治权力。具体选举资格、政党制度、竞选规则和职位权限待后续设计。

## 3.5 三条路径可以交织，不设置强制线性晋升树

例如：

-   玩家先投资科技公司，逐渐取得企业控制权，再凭借财富、声望和政治参与竞选城市管理职位。
-   玩家先成为城市管理者，任期结束后创办企业。
-   玩家同时持有多家企业股份，并参与城市政治。
-   玩家也可以主要作为投资者，不直接经营企业或担任公职。

企业家、投资者和城市管理者不是三种互斥职业，而是同一个世界中的不同身份、权力和活动。

## 3.6 权力边界与利益冲突

玩家的权力受到资本、持股比例、公司章程、股东投票、政治制度、选举结果、社会支持、法律和公共预算约束。

允许玩家同时拥有企业股权/经营影响力和政治身份，但长期需要考虑：

-   利益冲突和关联交易。
-   竞选资金与政治赞助。
-   公职人员持股和回避制度。
-   反腐、监管和法律约束。
-   政治职位不能成为无限制操纵市场的工具。

这些是后续设计方向，不要求首版全部实现。

## 3.7 玩家与自动世界的关系

玩家只是世界中的一个参与者。其他企业、居民、政党、候选人和政府都可以自主决策。世界不会因为玩家没有行动而停止运行。

首版先建立统一玩家账户、资产、持股、公司控制权和政治参与的概念模型与接口；具体制度逐步完善。

# 4. 世界地图与城市地图

游戏采用两个主要观察层级。未来可以增加更深入的区域/建筑管理界面，但首版不要求完整室内漫游。

## 4.1 第一层：区域战略地图

战略地图用于观察整个区域内多座城市及其联系。

主要表现：

-   多座城市的地理位置和相对距离。
-   城市领土、控制范围或行政边界。
-   道路、铁路、河流、港口等交通地理要素。
-   城市间贸易路线和物流联系。
-   城市人口、GDP、科技、产业等概览数据。
-   未来的国家边界、政治势力和区域联盟。

交互：

1.  点击城市节点，显示城市概况。
2.  进入城市，切换到该城市的内部地图。
3.  切换人口、经济、产业、科技等信息图层。
4.  选择贸易路线，查看商品流动和运输联系。

战略地图可以通过程序化地形、区域边界、道路网络、城市标记、图标和数据图层完成，不需要大量独立建筑图片。

## 4.2 第二层：城市内部地图

城市地图必须具有足够的视觉信息，不能简化成难以辨认的线条草图。

主要表现：

-   道路、路口、人行道和街区。
-   住宅、商业、办公、工业和公共设施。
-   公园、交通设施及城市装饰。
-   可辨识的建筑外观和土地边界。
-   不同区域的产业与人口分布。

交互：

-   点击街区，查看人口、就业、产业、地价等数据。
-   点击建筑，查看用途、经营主体、租金或其他属性。
-   点击道路或交通设施，查看交通与物流信息。
-   未来支持购买土地、调整用途、建设和升级建筑。

## 4.3 第三层：区域与建筑管理（后续扩展）

此层不是首版必须交付的独立 3D 场景，而是城市地图上的深入管理界面。

后续可支持土地购买、出售、住宅/商业/工业用地规划、建筑选址、建造、升级、拆除、企业选址和基础设施投资。

# 5. 人口核心系统

人口系统是整个世界模拟的基础核心。它负责人口总量、人口状态、人口迁移和人口分类等权威数据，并向其他系统提供人口群体和统计视图。

## 5.1 总人口是唯一权威来源

-   每座城市维护一个权威总人口数。
-   世界总人口等于所有城市总人口之和。
-   人口出生、死亡、迁移和人口分类变化必须经过人口核心管理。
-   其他系统不能直接篡改城市总人口。
-   企业招聘、裁员、居民收入变化或投票资格变化本身不会创造或删除人口。

## 5.2 经济状态：互斥且完备的人口分配

所有居民必须且只能属于一个基础经济状态：

\[ P = E + U + N \]

其中：

-   (P)：城市总人口。
-   (E)：就业人口。
-   (U)：失业人口（有劳动能力并正在求职，但尚未就业）。
-   (N)：非劳动力人口（例如儿童、退休者和暂不求职者）。

这是一套游戏内统计口径。劳动年龄、退休年龄和求职定义以后确定。

**就业人口 + 失业人口 +
非劳动力人口必须严格等于总人口，不能重复计算或遗漏。**

## 5.3 就业人口继续分配到雇主和岗位

就业人口不能只是一个汇总数字，还要能追溯到具体就业单位：

-   私营企业。
-   国有或公共企业（如未来设计）。
-   政府及公共机构。
-   自主经营者或个体经营者。
-   其他明确的就业类型。

所有雇主和就业类别的实际员工人数合计必须等于就业人口。

企业员工还要继续按岗位/职位类别分配，例如：

-   管理人员。
-   研发人员。
-   技术人员。
-   生产人员。
-   销售人员。
-   行政和支持人员。

企业各岗位人数合计必须等于该企业的实际员工总数。

初期采用人口群体和统计数量模拟，不为每个普通居民创建独立 AI
或独立实体。少数重要人物可以单独建模。

## 5.4 政治人口是另一种分类视图

政治人口是政治系统跟踪其政治态度、诉求和参与情况的居民集合。

-   具有投票资格的人口只是政治人口的子集。
-   暂时没有投票资格的居民仍可拥有社会诉求、满意度和政治倾向。
-   政治倾向、投票资格、政党支持和政治参与是人口的不同维度。
-   政治人口不能与经济人口相加计算总人口。

## 5.5 社会阶层由收入动态形成

不预先固定低、中、高收入群体的比例。

首版可以从低、中、高收入群体开始，但分类阈值待定。阶层应由个人/家庭收入、就业岗位、工资、资产收入和转移收入等共同决定。

非就业人口也可能拥有家庭收入、储蓄、养老金或政府转移支付，不能一律视为零收入或低收入。

后续可逐步增加财富、教育、职业和社会流动维度。

## 5.6 人口变化与跨城市迁移

人口核心管理：

-   出生和死亡。
-   城市迁入与迁出。
-   经济状态变化。
-   政治资格等人口分类变化。
-   收入和阶层统计所需的人口群体变化。

跨城市迁移必须采用原子事务：来源城市减少人口和目的城市增加人口应作为同一笔成功或失败的操作，避免人口丢失或重复。

# 6. 劳动力、企业与收入系统

## 6.1 劳动力市场

企业或其他雇主提出岗位需求、技能要求和工资报价。劳动力市场根据失业人口、技能、岗位要求、工资和其他规则进行匹配。

就业状态变化由人口/劳动力机制统一确认，企业不能凭空创造员工。

## 6.2 企业和岗位

企业系统负责：

-   企业实体和所属行业。
-   岗位类型、岗位数量和任职要求。
-   工资标准、薪酬政策和工资支出。
-   企业经营、生产、销售和财务数据。
-   企业的招聘、裁员需求和组织结构。

劳动力管理机制负责实际匹配和就业状态更新。企业读取已确认的员工数量和岗位分布。

## 6.3 工资和收入

不同企业、行业、职位、技能和企业薪酬政策会产生不同收入。

可以考虑以下简化工资关系：

\[ W = B `\times `{=tex}I `\times `{=tex}F `\times `{=tex}S \]

-   (W)：实际工资。
-   (B)：职位基础工资。
-   (I)：行业工资系数。
-   (F)：企业薪酬系数。
-   (S)：技能或岗位匹配系数。

公式仅为设计候选，具体系数、工资结算周期和规则待定。

收入数据形成居民/家庭收入分布，并动态影响阶层结构、消费能力、储蓄和投资。

# 7. 商品、市场与生产系统

商品系统和市场系统是核心模拟系统。商品按主要用途分为居民消费品和企业生产资料两大类。它们使用不同的需求生成规则，但共享基础市场机制。

## 7.1 商品的两大主要类别

### A. 居民消费品

供城市居民购买和消费，例如：

-   食品与饮料。
-   衣物。
-   日常生活用品。
-   家居用品。
-   药品。
-   消费电子产品。

不同人口群体会根据人数、消费倾向、收入和预算产生不同需求。

儿童、退休者、失业者也会消费；其消费资金可以来自家庭收入、储蓄、养老金或政府转移支付，不能因为没有工作就取消消费需求。

### B. 企业生产资料

供企业生产其他商品或提供服务时使用，例如：

-   金属与矿物。
-   木材。
-   化学原料。
-   电子元件。
-   机械零件。
-   能源与燃料。
-   其他基础材料和零部件。

不同产业和企业根据生产计划、生产配方和库存情况采购。

商品分类按照主要用途，不强制某种商品只能属于一个市场。例如电力可以同时供居民和企业使用。

## 7.2 商品基础数据

商品不需要 RPG 装备式的复杂属性。首版基础数据建议包括：

-   商品 ID、名称和主要类别。
-   计量单位。
-   基础参考价格。
-   当前市场价格。
-   市场库存或可售数量。
-   需求量。
-   供应量。
-   实际成交/购买量。
-   未满足需求量。

不同城市可以拥有不同的市场价格和库存状况。

## 7.3 市场需求、成交和库存

必须明确区分：

-   **需求量：** 市场参与者想购买多少。
-   **实际成交量：** 最终成功购买多少。
-   **未满足需求：** 想买但没有买到的数量。
-   **供应量：** 本期可供市场交易的商品数量。
-   **库存：** 市场或企业当前持有的商品数量。

不能把"需求"直接等同于"实际销售"。

## 7.4 居民消费需求

居民消费需求由人口规模、群体消费倾向、商品价格和可支配预算共同决定。

可以使用群体统计公式生成需求，例如：

\[ D_c = `\sum`{=tex}*g P_g `\times `{=tex}d*{g,c} `\times `{=tex}A_g \]

-   (P_g)：人口群体规模。
-   (d\_{g,c})：该群体对商品 (c) 的人均需求。
-   (A_g)：购买能力或预算约束系数。
-   (D_c)：商品总需求。

此公式是候选简化模型，不是最终平衡公式。

## 7.5 企业生产资料需求与生产配方

企业根据生产计划和配方采购原材料、零部件、能源等。

例如，一家面包工厂生产一定数量的面包，需要消耗相应数量的面粉、水和电力。

生产配方定义投入品与产出品之间的数量关系。企业生产受到以下因素限制：

-   原材料和零部件库存。
-   可用能源。
-   生产设备和资本。
-   员工数量与技能。
-   企业产能。
-   市场需求和销售预期。

商品不能凭空生产，原材料不能凭空出现。

## 7.6 企业库存与市场库存分离

建议企业拥有独立库存，市场拥有独立的可交易供应和成交记录。

-   企业可以持有原材料库存。
-   企业生产后可以持有成品库存。
-   企业可以将一部分成品投放市场，另一部分留在仓库。
-   市场成交后，商品从市场可售库存中扣除。
-   企业采购后，商品从市场供应转入企业库存。
-   销售不佳可能造成库存积压，促使企业降产。
-   原料短缺可能导致成本上升、减产甚至停产。

企业自有库存与市场库存不能重复计算。

## 7.7 市场价格

城市市场价格受供需缺口、库存、运输成本、采购竞争和其他市场因素影响。

建议采用渐进式价格调整，并设置合理边界，避免价格因单期供需波动而剧烈跳动或失控。

可以采用类似以下的简化候选关系：

\[ P\_{t+1} = P_t(1+kR) \]

其中 (R) 是供需缺口指标，(k)
是价格调整速度。实际公式、边界和价格平滑规则待后续设计。

## 7.8 商品与市场模块建议

  模块                职责
  ------------------- ------------------------------------
  Goods Catalog       商品目录、类别、单位和基础定义
  Consumer Market     居民消费品需求与购买
  Production Market   企业生产资料采购需求
  Market Engine       统一处理供需、价格、成交和市场库存
  Production System   企业生产配方、产能、投入和产出
  Trade System        城市间商品流动、运输成本和贸易

消费品市场和生产资料市场可以有不同需求生成逻辑，但应共享价格、库存和交易的基础机制，避免重复实现两套市场引擎。

# 8. 经济系统与游戏 GDP

## 8.1 游戏 GDP 的定位

城市可以统计一个明确标注为**游戏简化
GDP**的指标。它用于反映城市生产活动和经济规模，不声称等同于现实国家复杂的国民经济核算体系。

## 8.2 推荐口径：企业增加值汇总

建议：

\[ GDP\_{`\text{game}`{=tex}} = `\sum`{=tex}\_i VA_i \]

\[ VA_i = `\text{产出价值}`{=tex}\_i - `\text{中间投入}`{=tex}\_i \]

-   (VA_i)：企业或生产单位的增加值。
-   产出价值：本期生产商品或提供服务的价值。
-   中间投入：生产过程中消耗的其他商品和服务价值。

这样可以避免上下游企业的中间商品被重复计入 GDP。

**工资总额、企业营业额、股票市值都不能直接当作 GDP。**

## 8.3 简化估算的过渡方案

如果首版还没有完整生产、销售和投入产出模型，可以先使用员工数量、生产率、科技效率和资本效率估算企业增加值，再逐步升级到生产配方与市场成交驱动的模型。

示意候选关系：

\[ VA_i `\approx `{=tex}L_i `\times `{=tex}Q_i `\times `{=tex}T_i
`\times `{=tex}K_i \]

-   (L_i)：有效员工数量。
-   (Q_i)：基础生产率。
-   (T_i)：科技效率系数。
-   (K_i)：资本与设备效率系数。

该公式仅用于早期简化估算，正式模型待定。

# 11. 自动运行的世界模拟

## 11.1 世界能够独立运行

游戏世界不应依赖玩家逐项操作才能继续运转。

-   居民群体根据收入、需求和条件产生消费、就业和迁移行为。
-   企业根据市场需求、库存、成本、资金和预期决定采购、生产、招聘和投资。
-   政党和候选人根据支持群体、政治制度和竞选资源采取行动。
-   政府根据财政、政策目标和政治压力进行决策。
-   市场根据供需、库存和交易形成价格变化。

## 11.2 分层自动决策

建议采用三层决策：

1.  **人口群体层：**
    使用规则、概率和统计模型模拟消费、求职、迁移和阶层变化。
2.  **组织决策层：**
    企业、政府、政党等按照目标、预算、约束和规则自主决策。
3.  **重要人物层：**
    少数关键企业家、政治人物和管理者可以拥有更复杂的策略与个人属性。

不为数百万普通居民创建数百万个 AI Agent。

## 11.3 时间与可复现性

-   建立统一的模拟时间和结算流程。
-   可以考虑以月度作为主要经济结算周期，具体节奏待确定。
-   各系统按照明确顺序更新，避免相互使用不同时间口径。
-   随机事件使用可复现的随机种子，方便调试和解释。
-   重要结果应能够查看数据来源和形成原因，不依赖黑箱 AI
    随机决定经济事实。

## 12.3 系统交互原则

1.  模拟层与表现层分离。地图展示结果，不决定人口、价格或选举事实。
2.  每类数据有明确的权威系统。
3.  模块之间不直接修改彼此内部状态。
4.  跨系统变化通过命令、事件或明确接口完成。
5.  跨城市迁移、市场交易和库存转移需要定义成功/失败与事务边界。
6.  时间推进和结算顺序集中管理。
7.  优先使用可解释、可复现的规则与统计模型。
8.  为 AI Agent 提供稳定的模块边界、数据结构、接口和验收条件。

## 12.4 关键不变量

以下约束是架构和模拟正确性的基础：

### 人口守恒

\[ P\_{`\text{city}`{=tex}} = E + U + N \]

城市人口的经济状态分类必须互斥且完整。

### 就业分配守恒

所有雇主和就业类别的员工人数合计等于就业人口。

### 企业岗位守恒

一家企业各职位/岗位类别人数合计等于该企业员工人数。

### 世界人口汇总

世界总人口等于所有城市人口之和。

### 跨城市迁移原子性

迁出和迁入必须作为同一事务成功或失败。

### 库存守恒

采购、生产、销售、运输和损耗必须有明确的库存增减记录；不能凭空产生或消失商品。

### 生产投入产出约束

企业产出受到生产配方、原料库存、设备、员工和产能限制。

### 市场成交约束

实际成交量不能超过可交易供应量，也不能超过有效购买需求；未满足需求单独记录。

### GDP 口径约束

GDP
按增加值或明确的游戏简化生产口径统计，不能把工资、营业额或股票市值直接重复计入。

# 14. 首版原型范围

首版目标不是完成所有模拟系统，而是验证固定资产包能否支撑多城市战略地图与城市内部地图，以及
TypeScript + Phaser + Electron 技术链是否顺畅。

## 14.1 首版地图原型

-   一张区域战略地图。
-   三座相互独立的城市。
-   城市具有不同的相对位置和区域范围。
-   城市之间显示基础交通/贸易连接线。
-   点击城市进入城市内部地图。
-   至少一座城市具有可辨识的完整街区。

## 14.2 首版城市地图

至少展示道路、路口、人行道、住宅区、商业区、办公/科技产业区、工业区和公共设施或公园。

优先使用正式主资源包中的素材，不临时混入大量风格不同的素材。

## 14.3 首版交互

-   区域地图与城市地图切换。
-   城市概况面板。
-   城市内部街区点击。
-   基础区域信息面板。
-   人口、经济、产业等图层切换 UI 原型。
-   Electron 桌面应用启动和退出。

首版地图原型可以使用演示数据，不要求所有模拟机制都真实运算。

## 14.4 首版模拟验证建议

地图原型之后，逐步验证最小经济闭环：

1.  创建一个城市和权威总人口。
2.  将人口分配为就业、失业和非劳动力。
3.  将就业人口分配到雇主和岗位。
4.  为企业配置工资和简单生产能力。
5.  定义少量消费品和生产资料。
6.  让居民群体产生消费需求。
7.  让企业按生产配方采购原料、生产和销售。
8.  计算企业收入、成本、工资和简化增加值。
9.  汇总城市游戏 GDP。
10. 推进下一期，观察就业、收入、库存、价格和人口需求反馈。

## 14.5 首版明确不做

-   不做完整国家系统。
-   不做军事系统。
-   不做完整外交系统。
-   不做复杂真实物流仿真。
-   不做逐栋独立建模。
-   不做人物自由行走和复杂动画系统。
-   不因追求完美视觉而无限扩充素材。
-   不在地图原型阶段提前实现全部经济和政治规则。
-   不为所有普通居民创建独立 AI Agent。

# 17. 版本决策摘要

截至 2026-11-01，项目已经确认的关键决定：

1.  从高美术成本的 3D 城市项目转向地图驱动的 2D 多城市经济社会模拟。
2.  技术路线确定为 **TypeScript + Phaser + Electron**。
3.  世界从多个独立城市开始，未来再扩展为多个城市组成国家。
4.  游戏有区域战略地图和城市内部地图两个核心层级。
5.  城市内部保留有辨识度的 2D 美术资产，不采用过度简化的线条地图。
6.  首批固定美术资源选用 **Rasak Modern Tilesets + Kenney UI
    Pack**；Kenney Roguelike Modern City 与 Modern City Extension
    作为独立 CC0 备用组合；Pulse Everyday Streets 暂缓。
7.  人口系统是世界模拟的基础核心：每城总人口唯一权威，经济状态分类互斥且完备，人口就业分配到雇主和岗位。
8.  人口与企业、劳动力、工资、收入阶层和消费需求联动。
9.  商品分为居民消费品和企业生产资料两大主要用途；商品市场、生产配方、库存和价格是核心模拟机制。
10. 企业不能凭空获得员工、原材料或产出；市场必须区分需求、成交、未满足需求和库存。
11. 城市游戏 GDP 采用明确标注的简化口径，优先按企业增加值汇总。
12. 城市之间通过贸易、运输和供应链联系起来。
13. 世界由人口群体、企业、政党和政府等自主运行；玩家能够影响世界，但不是唯一决策者。
14. 玩家以独立投资者身份开局，资本投资、企业经营、政治治理是同一玩法中的三条可交织发展路径，不是互斥职业或独立模式。
15. 首版先完成固定资产库和地图原型，再逐步建设人口、劳动力、企业、商品市场、生产和
    GDP 的最小闭环。

**当前最近一步：** 完成 Rasak Modern Tilesets 与 Kenney UI Pack
的下载、许可归档、目录检查和实际拼装预览；随后启动 TypeScript + Phaser +
Electron
地图原型。之后优先验证人口---就业---企业---商品市场---生产---GDP
的基础闭环。
